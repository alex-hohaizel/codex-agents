# Universal installation and technical publication

The current product supports one installer workflow across Windows, macOS and
Linux on the declared x64/ARM64 targets. Keep the same skill IDs, resource
closure, role identities, recovery semantics and acquired-major rights.

The owner requested a published technical installer release on the default
branch after the local commercial candidate. `main` remains the default branch;
this authorization does not start a shop, finalize legal terms, accept partner
contracts, process payment or purchase signing/services.

## One buyer journey

The root `START_HERE.html` and Ukrainian entry must exist in Git, so even GitHub's
automatic source ZIP has a visible start. They identify the ready Release assets.
A ready installer contains its Node and Python runtimes, full reviewed product
sources/resources, executable OS launchers, licenses and a precise inventory.
Opening the platform launcher starts a local browser wizard. HTML does not
silently execute system commands. The wizard uses the existing audited Python
setup with explicit plan approval; it does not duplicate the updater.

Expose prerequisite/account status separately from installed files and actual
native discovery. Installing skills does not create a Codex account, include
model usage or guarantee domain SDKs/services. Keep the existing CLI, source
imports, optional workbench and advanced recovery paths.

## Native compatibility and safety

Use actual Windows locking and private ACLs, non-destructive process queries,
UTF-8/LF byte preservation, junction/reparse guards and valid Windows names.
Keep existing POSIX permissions/ownership guarantees. Vendor runtimes are pinned
by exact version, source URL, SHA and notices. Generated client resources have
an explicit build inventory. No ignored developer state or credentials may
enter source, runtime or distribution packages.

The browser service binds loopback, authenticates an owner session and checks
Host/Origin/CSRF. Browser requests cannot choose arbitrary commands, filesystem
targets, plans or journals. Mutation approval binds the saved plan hash. A
refresh or lost response reconciles actual journal state before any replay.

## Evidence and release

Run the actual ready package on native Windows, macOS and Linux runners for
both declared CPU architectures. Verify clean install, repeat, recognized
predecessor upgrade, local drift, real interruption, competing updater,
rollback/uninstall, native skill discovery, private permissions and workbench
state/schema recovery. Run browser buttons against the real engine; mocked
HTTP or a static screenshot cannot certify installation.

Publish only reviewed, clean-source artifacts after the exact merged commit
passes release checks. Keep the root documentation, localized instructions,
release notes, manifests, runtime notices, checksums and GitHub attestations
consistent. Confirm the public `main`, visible latest Release and actual asset
downloads. A prepared workflow or local ZIP is not publication. Device/OS
minimums, signing, model tasks and commercial approval keep separate scopes.
