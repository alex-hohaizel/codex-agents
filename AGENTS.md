# Codex Agent System repository

Use this file as an entry point. Read the sources and checks affected by the task. A small local change may need only its file and one verification.

- Keep the 33 stable core names, optional skill boundaries, role identities, icons and colors. Preserve native project requirements, decisions, permissions, and deferred work. Existing projects and generated agents have separate adoption records.
- Keep private chats, credentials, databases, raw audit data and account-specific packages out of the reusable repository.
- English is the canonical instruction language. Preserve commands, stable IDs and original quotations. Maintain equivalent complete guides in the advertised languages when the public workflow changes. Follow the required language for user-facing work.
- Record source integrity, runtime behavior, native discovery, independent review, installation and product acceptance at their respective scopes. Check evidence against the exact inputs and current target.

| Work | Open when applicable |
| --- | --- |
| Edit or publish a release | [Update contract](governance/UPDATE_CONTRACT.md), [requirements](governance/requirements.csv), [current component versions](releases/current.json), and the current installation guide. Confirm the actual remote branch. Publish the authorized verified change and confirm the resulting GitHub revision. |
| Continue or adopt work in a product | The product's native checkpoint, requirements, decisions, identity, toolkit lock and handoff. [Context contract](standards/context-capsule.md) |
| Change a production artifact | [Production quality](standards/production-quality.md) and its applicable medium profile. Preserve accepted originals. Check an actual consumer for a representative result before batch work. |
| Coordinate work with resume, risk or an unknown effect | [Resumable work](governance/RESUMABLE_WORK.md). Check the current source pins, owner, scope, bounds and unknown operations. Retain the next action and reconcile an uncertain destination before resending. |
| Create or change a skill or role | That component's instructions, relevant references, and [validation](governance/VALIDATION.md). Verify appropriate triggering and a meaningful result. Retain provenance for the maintained source and generated copies. |
| Change the campaign | [Active campaign](marketing/CURRENT_CAMPAIGN.json) and its linked README. Preserve product identity, same-language captions, and accessible public navigation. Run the campaign's build and validation from the owning directory for artwork or delivery changes. |

An approved release includes affected sources, version and evidence records, translations, actual packages, installation and recovery as applicable. Use the active branch (`main` unless the owner specifies another) and verify GitHub read-back. Repository publication, local adoption and any action on a product each have their own scope. The owner retains decisions about visibility, licensing, spending and production deployments.
