<a name="install"></a>
## Встановіть і перевірте, що Codex знайшов навички

### Готовий інсталятор для Windows, macOS і Linux

Якщо довірена доставка видала JSON підтвердження покупки або entitlement, відкрийте **Збережіть документ покупки · необов’язково** й виберіть оригінальний файл перед підготовкою плану. Він залишається приватним поза пакетом і папками навичок. Новий документ скасовує старий план та підтвердження: підготуйте й перегляньте новий план. Оновлення автоматично зберігає наявний запис покупки. Збереження документа не перевіряє підпис покупки й не надає прав. Технічний установник працює й без документа покупки.

Завантажте готовий архів **Universal** або пакет своєї ОС та архітектури зі [стабільного релізу](https://github.com/alex-hohaizel/codex-agents/releases/latest). Повністю розпакуйте його, прочитайте `ПОЧАТИ.html` та відкрийте `Start.cmd` у Windows, `Start.command` у macOS або `Start.sh` у Linux. Python, Node і зібраний інтерфейс уже в готовому пакеті. Автоматичний Source code ZIP GitHub призначено для роботи з джерелами. Майстер має український та англійський інтерфейси.

Перевірте комп'ютер, підготуйте план, перегляньте папки й конфлікти, погодьте точний план та встановіть його. Далі звірте файли й перевірте виявлення у Codex. Типовий склад: 33 навички, Orchestrator, профіль і 12 ролей. Використовуйте власний акаунт Codex. Створіть пробний проєкт, відкрийте папку та Codex, скопіюйте запит у цю сесію. Майстер не запускає модель. Зберігайте журнал; відновлення використовує обрану операцію й той самий план. [Повний шлях установлення й відновлення](../INSTALL.md#recommended-local-browser-installer)

Python/venv та Node ваших проєктів зберігають пріоритет. `AGENT_SYSTEM_PYTHON` указує інтерпретатор службових скриптів комплекту. Maintenance — окремий інструмент власника: використайте `product/maintenance-skill` із пакета або `maintenance-skill` репозиторію через штатний менеджер навичок, перегляньте джерело й ціль, потім перевірте. Моделі й сторонні послуги мають власні акаунти та вартість.

Особисті навички розміщуються відповідно до нативного Codex. `CODEX_HOME` — це домашня папка Codex, обрана для цієї сесії; аудит показує точну ціль.

| Обсяг встановлення | Папка навичок |
| --- | --- |
| Особисті навички Windows | `CODEX_HOME/skills`, типово `<selected-home>/.codex/skills` |
| Особисті навички macOS / Linux | `<selected-home>/.agents/skills` (типово `~/.agents/skills`) |
| Навички проєкту в усіх системах | `<project>/.agents/skills` — без змін |

Для попереднього особистого встановлення Windows у `<selected-home>/.agents/skills` підготуйте новий аудит поточним установником. Переглянутий план показує основну ціль і виведення розпізнаних керованих старих копій; підтримувані зміни лише іконок основних навичок зберігаються. Невідомі зміни джерел або правил, конфліктні копії чи іконки потребують узгодження замість примусової заміни. Не переносьте й не видаляйте ці дерева вручну. Погодьте точний план міграції, звірте файли та виявлення у свіжому Codex, збережіть журнал і резервні копії. Відкат за цим початковим журналом повертає попередні шляхи й керовані байти; вже збережені журнали використовують свої перевірені початкові корені. [Вибір кореня й міграція](../INSTALL.md#personal-skill-roots)

### Поглиблений шлях із джерел

1. Відкрийте стабільний реліз `alex-hohaizel/codex-agents`. Для термінальної процедури на macOS або Linux потрібні Bash, Python 3.9+, Git, GitHub CLI (`gh`) із входом в обліковий запис і Codex. Можна попросити Codex пояснити кожну дію українською та зберігати точні команди й шляхи.
2. Пройдіть встановлення з атестацією. Інструмент звіряє хеш пакета та атестацію GitHub із комітом, робочим процесом і маніфестом. Для порожнього профілю виберіть чисте встановлення, для наявного комплекту вкажіть його підтверджену версію. [Стабільний реліз](https://github.com/alex-hohaizel/codex-agents/releases/latest) · [Точні команди](../INSTALL.md#steps)
3. Перевірте в аудиті 33 назви, місце встановлення, збереження іконок і посилань на них та відкриті конфлікти. Застосуйте перевірений план і використайте повернений журнал для звірки файлів. Керований профіль і дванадцять ролей установлюються з окремим аудитом і журналом. [Профіль і ролі](../INSTALL.md#profile-and-roles)
4. За потреби встановіть Orchestrator і maintenance окремо. У панелі Agent Atelier відкрийте попередній перегляд конкретного джерела, звірте ціль і зміни, застосуйте та перевірте. У Codex можна скористатися штатним менеджером особистих навичок і повним каталогом додаткової навички. [Додаткові компоненти](../INSTALL.md#optional-components)
5. Відкрийте новий чат Codex у папці потрібного продукту. Викличте `$agent-foundry` або потрібну навичку. Якщо середовище показує її шлях, звірте його з установленим джерелом. Потім завершіть задачу з видимим результатом. [Як Codex знаходить навички](https://learn.chatgpt.com/docs/build-skills#where-codex-loads-local-skills)

ChatGPT Work використовує власний інтерфейс особистих навичок. Скористайтеся пакетом Work і перевірте, які записи це середовище зберегло й завантажило. Локальне оновлення Codex є окремою дією. [Пакети](../../governance/PACKAGES.md)

<a name="first-task"></a>
## Зробіть першу правку

Створіть тимчасову папку та відкрийте в ній новий чат Codex. Додайте `# Cheklist` у `README.md`, а в `notes.txt` напишіть рядок, який треба зберегти. Зверніться українською:

```text
Виправ орфографію заголовка в README.md. Збережи notes.txt без змін.
Покажи виправлений заголовок і як ти перевірив обидва файли.
```

Перевірте, що заголовок тепер `# Checklist`, а вміст `notes.txt` збережено. Для такої задачі достатньо прямого виконання. Для більшого проєкту дайте Orchestrator очікуваний результат, папку проєкту, дозволені зміни та спостережувану умову приймання. Наприклад, попросіть перевірити оформлення покупки, зберегти погоджений платіжний контракт і повернути відтворювані проблеми. [Відтворювана перша задача](../../START_HERE.md#install-and-verify)

<a name="workflow"></a>
## Виберіть маршрут і збережіть контекст

Виконайте задачу напряму, викличте навичку або доручіть вибір `$atelier-orchestrator`. Для життєвого циклу застосунку, бота чи гри оберіть директора. `$agent-foundry` підходить для повторюваної роботи агента чи команди. Погодьте паспорт перед побудовою і перевірте підготовлений пакет на вихідній задачі. Для повторно вживаного процесу із чітким тригером і тестами викличте `$design-specialist-skills`.

### Harness і повноваження

Codex надає середовище виконання, інструменти та механізм дозволів. Репозиторій надає `AGENTS.md`, описи й ресурси навичок, предметні контракти, ролі та перевірки. ### Ролі й субагенти

Делегуйте окремий результат або незалежну перевірку. Назвіть виконавця, ревізію, вхідні шляхи, дозвіл на запис, результат, обмеження, умову зупинки та місце повернення. Призначте одного автора для спільного стану. Отримайте фактичний результат виконавця перед інтеграцією. [Маршрути й субагенти](../OPERATING_MODEL.md#routes-and-subagents)

Якщо проєкт веде свій реєстр задач у локальній проєкції, підготуйте й перегляньте перепланування та застосуйте погоджену зміну. <a name="context"></a>
### Капсули контексту

Почніть з авторитетних вимог, ідентичності, поточних рішень і контрольної точки проєкту. Зафіксуйте точні хеші джерел, застосовні вимоги, дозволені дії, відкладену роботу, очікуваний результат, невідомі наслідки й наступну дію. Якщо джерело змінилося або недоступне, перевірте пов’язані вимоги повторно. Передавання роботи переносить вибірку в іншу задачу чи середовище зі збереженням авторитету вихідних джерел.

За чистої установки майстер відкривається англійською навіть на українській ОС чи в українському браузері. Виберіть англійську або українську в майстрі. Явний вибір зберігається при перезапуску на новому порту. Workbench використовує коректну явно обрану мову інтерфейсу, далі збережений вибір, далі англійську. Для задачі явно виберіть мову результату або збережіть зафіксовану мову проєкту. Керований launcher запитує GPT-6.2 Sol Ultra за доступності моделі й рівня міркування в акаунті покупця. Оплату для цього релізу вимкнено. Оригінальний офлайн-документ покупки можна зберегти окремо.

Запишіть `preferred_language` у контекст проєкту й передавайте його іншим виконавцям. Зберігайте команди, селектори, ідентифікатори, посилання та оригінальні цитати. <a name="retrieval"></a>
## Додайте пошук знань і RAG

Почніть із перевірених шляхів, точних ID, структурованих запитів і пошуку за словами. Додайте RAG, якщо релевантні докази регулярно важко знайти. Порівняйте пошук за словами, семантичний і гібридний пошук на одному дозволеному корпусі перед вибором індексу чи векторного сховища. Перевірте знаходження потрібних фрагментів, точність цитат, коректну відмову без даних, кілька мов, відкликані та застарілі джерела, суміжні приватні проєкти, затримку й витрати. Зберігайте права та версію джерела для кожного фрагмента, перевіряйте права перед пошуком і цитуванням, підтримуйте видалення та перебудову. Знайдений текст використовується як дані; дозволами керують проєкт та інструменти.

`$chatbot-atelier-knowledge` допоможе з корпусом, пошуком, відповідями на основі джерел і супроводом. DATA, ANALYSIS, LLM, PREDICTION, ADAPTATION, MEDIA й EVALUATION є профілями для відповідних задач. Активуйте потрібний профіль і звірте фактичний результат у споживача. [Технічний посібник із пошуку](../OPERATING_MODEL.md#retrieval-and-rag) · [Профілі ШІ й даних](../../standards/ai-production.md)

<a name="evals"></a>
## Перевірте поведінку за допомогою evals

Зафіксуйте типові вхідні дані, ревізію джерел, модель, середовище, очікуваний результат, випадки відмови й межі часу або вартості. Перевірте явний і природний запуск, схожі запити, заборонений доступ, застарілі посилання та відновлення. Перегляньте точний артефакт у його реального споживача. Окремо запишіть структурні перевірки, поведінку в Codex, квитанції дій та незалежне приймання. Сирі запити й приватні шляхи залиште в ізольованих матеріалах тесту.

З кореня репозиторію запустіть малу реальну перевірку, маючи Codex CLI та підтримуваний вхід:

```bash
receipt_dir="$(mktemp -d)"
python3 -B evaluations/native_canary.py --case p01-direct --output "$receipt_dir/direct.jsonl"
```

Перевірка виправляє очікувану помилку в тимчасовому проєкті та звіряє інший файл. Набір тестів також охоплює передавання задачі, погоджений паспорт і перший виклик згенерованої навички. Твердження про зовнішній продукт потребує доказів у його середовищі. [Тести, дані й квитанції](../../evaluations/README.md) · [Валідація](../../governance/VALIDATION.md)

<a name="workbench"></a>
## Працюйте в Agent Atelier у Windows, macOS або Linux

У готовому пакеті є `Start-Workbench.cmd` для Windows, `Start-Workbench.command` для macOS та `Start-Workbench.sh` для Linux. Відкрийте відповідний файл; готовий інтерфейс не потребує npm-збирання. Окремо звірте заявлені нативні перевірки релізу: наявність runtime не замінює доказу запуску. Нижче збережено додатковий шлях збирання для розробників; наступні дії з проєктами та відновленням застосовуються до обох шляхів. [Готова панель і відновлення даних](../commercial/WORKBENCH_RUNTIME.md)

1. Відкрийте поточні джерела та зберіть застосунок за зафіксованим файлом залежностей Node.js. Із `apps/agent-atelier/` виконайте:

```bash
npm ci --ignore-scripts
npm run build
node launcher/atelier.mjs start
node launcher/atelier.mjs status
node launcher/atelier.mjs doctor
```

2. У локальній панелі знайдіть потрібний проєкт і перевірте доступне охоплення. Зареєстровані Codex проєкти можуть з’являтися без чатів. Історія й артефакти відкриваються на вимогу. Перегляньте точну папку та явно прив’яжіть її. Демо містить вигадані записи.
3. Відкрийте запис і наступну дію, прив’язану до джерела. Перенесіть її у форму задачі, звірте мету, приймання, вхідні дані, дозволи й навички, перегляньте маршрут Orchestrator. Підготуйте задачу, запустіть узгоджену роботу та звірте результат і квитанцію. Продовжуйте наявний чат за підтримуваних контексту й ідентичності, якщо він вільний. Інакше підготуйте окрему обмежену задачу.
4. У розділі підключень перевірте доступність застосунків, плагінів і конекторів. За відповідної підтримки панель знаходить офіційну документацію OpenAI, показує й завантажує PNG із Codex, шукає зображення й аудіо Openverse із походженням та ліцензією і читає метадані репозиторію через наявний вхід GitHub CLI. Вибирайте дії, підтримувані вашим середовищем та обліковим записом. [Посібник панелі](../../apps/agent-atelier/README.md) · [API та межі підключень](../../apps/agent-atelier/shared/API.md)

<a name="operations"></a>
## Експлуатація, відновлення й оновлення

<a name="permissions"></a>
### Інструменти й дозволи

Перед записом через інструмент звірте дію, ціль, дозвіл, вартість, обмеження й очікувану квитанцію. Після тайм-ауту чи відсутньої квитанції прочитайте авторитетний стан точного запиту. Повторюйте дію за чинного дозволу та перевіреного захисту від дублювання. Залишайте видимими невідомі наслідки й докази. Оцінюйте результат у фактичному продукті окремо від підготовки, виконання команди та створення файлу. [Дії інструментів і докази](../OPERATING_MODEL.md#tools-evidence-and-recovery)

### Відновлення й оновлення

Для оновлення використовуйте стабільний пакет і точний план. Зберігайте журнали та наявний стан. Після переривання звірте ціль перед продовженням. Для відкату ядра, профілю або додаткової навички використовуйте її журнал. Збережіть базу та файли панелі за документованою процедурою, перезапустіть на належному каталозі даних і перевірте перелік проєктів і малу задачу. Продуктові дані, нативні чати й облікові записи мають свої процедури відновлення. [Встановлення й відкат](../INSTALL.md#rollback) · [Відновлювана робота](../../governance/RESUMABLE_WORK.md)

Після завершеного відкату відкрийте поточний інсталятор і підготуйте новий план перед наступним установленням. Збережіть початковий план і журнал відновлення: вони дозволяють розпізнати відновлений launcher і збережені права. Пізніші локальні правки launcher лишаються конфліктом; не видаляйте записи встановлення для обходу перевірки.
