# Установлення Codex Agent System

Готовий технічний реліз має локальний інсталятор для Windows, macOS і Linux. Комерційні умови Solo/Team та доставка залишаються **release candidate** для розгляду власником, а не активною пропозицією продажу.
Покупець використовує власний сумісний Codex із чинним входом. Моделі,
API та сторонні сервіси оплачуються окремо. [Склад](../../commercial/product.json)
і [умови ліцензії](LICENSING.md) описують права на сам комплект.

## Отримайте й перевірте

Для технічного релізу завантажте готовий Universal або пакет своєї платформи з [офіційного стабільного релізу](https://github.com/alex-hohaizel/codex-agents/releases/latest) та повністю розпакуйте його. Автоматичний Source code ZIP GitHub містить джерела й навігаційну сторінку; для зібраного інсталятора потрібен готовий Release asset. Звірте точний commit, контрольні суми, походження та нативні квитанції цього артефакту. Технічна публікація не видає документ придбання й не запускає продажі.

Окремий довірений комерційний шлях нижче збережено для доставки, яку дозволить власник:


Потрібні архів Solo або Team, документ придбання/ліцензії, release index
і підпис із довіреної доставки продавця. Отримайте відкритий ключ перевірки
окремим довіреним шляхом. Контрольна сума в самому архіві не встановлює
походження. Для локального RC використовуйте виданий тестовий відкритий ключ.

Технічний шлях перевірки наведено в [англійському посібнику](BUYER_GUIDE.md#receive-and-verify).
Він потребує OpenSSL із підтримкою Ed25519. Якщо його немає, встановіть
сумісний OpenSSL або використайте незалежно довірений канал продавця.
Не довіряйте ключу лише тому, що він лежить у завантаженому ZIP.

## Установіть і почніть

У перевіреній папці відкрийте `ПОЧАТИ.html` або `START_HERE.html`, а потім відповідний запуск:

| Windows x64 / ARM64 | macOS Intel / Apple Silicon | Linux x64 / ARM64 |
| --- | --- | --- |
| `Start.cmd` | `Start.command` | `Start.sh` |

Він відкриває приватний локальний майстер у браузері. Python, Node й зібраний інтерфейс уже в готовому пакеті; окреме встановлення цих runtime, npm-збирання й права адміністратора для цього шляху не потрібні. HTML самостійно не виконує встановлення. Підказки довіри ОС та статус підпису продукту залишаються окремими фактами релізу. Якщо Linux-розпакування втратило право виконання, увімкніть його у властивостях файлу або виконайте `chmod +x Start.sh`, потім `./Start.sh`.

Якщо довірена доставка видала JSON підтвердження покупки або entitlement, відкрийте **Збережіть документ покупки · необов’язково** й виберіть оригінальний файл перед підготовкою плану. Він залишається приватним поза пакетом і папками навичок. Новий документ скасовує старий план та підтвердження: підготуйте й перегляньте новий план. Оновлення автоматично зберігає наявний запис покупки. Збереження документа не перевіряє підпис покупки й не надає прав. Технічний установник працює й без документа покупки.

Виберіть українську мову, перевірте комп'ютер і підготуйте план. Звірте цільові папки, зміни, збережені налаштування й конфлікти. Погодьте саме цей план, установіть його, звірте файли та перевірте виявлення у Codex. Рекомендовано 33 основні навички, Atelier Orchestrator, профіль і 12 ролей. Maintenance залишається окремим інструментом власника; повне джерело `product/maintenance-skill` доступне для штатного менеджера навичок. Для окремої панелі є `Start-Workbench.cmd`, `Start-Workbench.command` і `Start-Workbench.sh`. Установлення не створює модель чи акаунт зовнішнього трекера.

Особисті основні навички та Orchestrator у Windows використовують `CODEX_HOME/skills`, типово `<selected-home>/.codex/skills`; у macOS/Linux — `<selected-home>/.agents/skills`. Проєктний шлях `<project>/.agents/skills` не змінюється. Аудит показує основні цілі та погоджене виведення розпізнаних старих особистих копій Windows із `.agents/skills` зі збереженням підтримуваних змін іконок основних навичок. Невідомі правки чи конфліктні копії блокуються замість перезапису. Збережіть точний журнал міграції: відкат повертає його початкові корені й керовані байти, профіль/ролі та збережений entitlement. Уже збережені журнали зберігають свої перевірені шляхи. [Нативні корені та контрольована міграція](../INSTALL.md#personal-skill-roots)

Створіть пробний проєкт кнопкою майстра, відкрийте папку та Codex через підготовлений запуск, скопіюйте запит у цю сесію. Запуск прив'язаний до нової пробної папки й установлених ролей. Використовуйте власний Codex; перевірте виправлений заголовок та незмінні нотатки. Майстер лише готує вправу: він не виконує модель і не засвідчує її результат.

Python/venv і Node вашого проєкту зберігають пріоритет. `AGENT_SYSTEM_PYTHON` та `AGENT_SYSTEM_NODE` указують точні runtime службових скриптів комплекту. Якщо сумісного Python немає, доступний убудований запасний інтерпретатор. Глобальний PATH і реєстр не змінюються. Для командного шляху запустіть відповідний `Start` із `--help`; це той самий рушій:

Запустіть `doctor` і `audit`, перегляньте цілі, склад та конфлікти,
потім застосуйте `install` із точним ідентифікатором плану. Збережіть
план і журнал поза папками навичок. Після `verify` виконайте `discover`
у свіжому Codex і `first-task` або `prepare-first-task`. Якщо хост потребує явної реєстрації ролей,
використайте параметри запуску, які повернув setup. Файл ролі не доводить її
реальну активацію. Точні параметри доступні через `--help`.

Скопіюйте `examples/first-task` у пробну папку. Попросіть встановлений
Orchestrator виправити лише помилку заголовка й зберегти `notes.txt`.
Звірте результати. Виконання використовує ваш чинний акаунт Codex.

## Оновіть, відновіть або видаліть

Зберігайте ліцензійний документ і попередній пакет. Оновлення в межах major
не скасовує вже придбаних прав. Для нової перевіреної версії повторіть аудит.
Незнайома локальна правка — конфлікт для розгляду; універсального force немає.

Після переривання оновіть розділ продовження й відновлення, оберіть перевірену операцію та використайте той самий план і її журнал для продовження. Невизначений результат спочатку перечитайте.
Rollback використовує власний журнал. Видалення звіряє належність файлів
і зберігає змінені користувачем файли, сторонні навички й проєкти.
Дані панелі мають окрему схему й резервну копію.

Для підтримки передавайте версію, платформу, посилання на замовлення
й проблемний крок. Не передавайте ключі, токени, приватні проєкти чи чати.

Готовий Universal містить інтерфейс панелі та runtime для шести заявлених настільних цілей. Використайте відповідний `Start-Workbench` і [посібник runtime та відновлення даних](WORKBENCH_RUNTIME.md). Збережений попередній комерційний конструктор також може вкладати окремі Mac-архіви в `runtime/`; вони мають власний `Launch.command`. Наявність пакета, нативний запуск на ОС/CPU, графічна взаємодія, підпис і модельні задачі мають окремі докази. Звіряйте фактичні перевірки та межі за квитанціями точного Release; один локальний прогін не доводить шість платформ.

Для розширеного запуску підтримується `--entitlement`: наприклад, `./Start.command --entitlement "/path/to/confirmation.json"` на macOS або відповідний `Start.cmd` / `Start.sh`. Графічний вибір файла виконує той самий покупецький аудит. Зберігайте оригінал документа й отримуйте його лише з довіреної доставки.
