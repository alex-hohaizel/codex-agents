# Local API 1

Production serves `dist/client` and `/api/v1` on `127.0.0.1:4317`. Vite proxies `/api` and `/health` to loopback in development. No external CORS.

The launcher verifies a listener HMAC proof and opens a 60-second one-use token in `#atelier_launch=...`. The client removes that fragment before `POST /api/v1/session {launch_token}` with trusted Origin and JSON content type. Successful claims set an HttpOnly SameSite=Strict cookie and return `{status:'ready',csrf_token}`. `GET /api/v1/session` requires that cookie or the launcher's private `X-Atelier-Control` key. Static loading never grants a session. Private GETs require the cookie; commands also require trusted Origin/Host and `X-Atelier-CSRF`. Reopen the launcher after expiry/restart. This controls a personal Mac; it does not isolate a malicious process running as the same OS owner.

- `GET /health`: liveness/instance ID; optional bounded `owner_probe` nonce returns `owner_proof`, never a session/key.
- `GET /api/v1/bootstrap`: `{api_version,version,instance_id,csrf_token,locale,projects,jobs,tasks,skills:{entries,summary},capabilities:{codex,work},activity,metrics}`.
- `GET /api/v1/projects/:id/workspace`: `{project,sources,requirements,decisions,artifacts,identity,readiness,jobs,tasks,context,warnings,service_decisions,service_evidence}`. Native records stay authoritative/read-only.

The workspace also exposes `current_checkpoint:{phase,completed,in_progress,next,source_ref,source_sha256,status:'declared'}` only from one explicitly bound, required `role:'checkpoint'` JSON source whose loaded bytes match its current pin. It preserves bounded source text and text arrays under the existing privacy redaction policy; it does not change native `project.phase`, task status, authority or acceptance. Missing, ambiguous, stale or unsupported checkpoint data yields `current_checkpoint:null` and a nonblocking `current_checkpoint_gap`; existing context-binding gates remain separate. No checkpoint is guessed for legacy projects. Phase is bounded to 2,000 characters, each of the two arrays to 100 text entries of 4,000 characters, and `next` to 4,000 characters.

- `GET /api/v1/projects/:id/source?path=...`: bounded `{path,sha256,bytes,content}`; no traversal, linked escape, credentials or private service-root overlap.
- `GET /api/v1/projects/:id/artifact?path=...`: image/audio/video/PDF bytes; active HTML/SVG never runs.
- `GET /api/v1/projects/:id/diff?path=optionalRelativeFile`: real bounded Git working-tree `{diff,truncated,source,path}`; external diff/textconv disabled. Missing Git is typed unavailable.
- `GET /api/v1/projects/:id/threads?cursor=...`: actual host cwd-scoped list; discovery is not ownership.
- `GET /api/v1/skills?q=...`; `/skills/:source_id/source`: `{name,canonical:{path,sha256,content},installed:null|{sha256,content},installation_error,primary_equal,scope}`. URL-encode IDs, including `host:`.
- `GET /api/v1/jobs/:id`, `/doctor`, `/commands/:id`, `/events?after=sequence` (SSE).
- `POST /api/v1/commands`: `{command_id,operation,project_id?,expected_revision?,payload:{...}}` → `{command_id,status,result?,error?}`. Same identity/input returns its durable receipt; changed input conflicts. Dispatch can finish while its real job continues. Event sequence IDs are durable; refresh records after events.

`project.preview {root}` → `{preview_id,...observedProject}`; `project.bind {preview_id,name?,view_profile?}` → `{project}`. Project and canonical service-data roots must be disjoint. No automatic HOME traversal/migration. `project.profile {view_profile}` selects `app|bot|game|agent|research|document|mixed|generic` presentation without native mutation. `project.refresh {}` rechecks revision.

`task.prepare {objective,acceptance,scope:'read-only'|'workspace-write',allowed_paths:relativeDirectories[],deadline_seconds:30..3600,selected_skills?:source_id[],planning_only?:boolean,capability_scope?:{public_web_read:boolean},thread_binding_id?,memory_mode?:'inherit'|'disabled'}` → `{task,capsule}`. It preserves native must requirements/dependency closure, original references, source hashes and scope. At most four distinct selected skills use verified immutable full-tree service snapshots and actual `skill` inputs, not installation. New prepared selections include a private `archive_root` plus an owned, data-directory-bound `execution_transport`; `snapshot_root` and `path` refer to its separate read-only execution copy. Only the exact selected subtree receives a read grant. Canonical source, archive, execution bytes, complete selection membership and task identity must still match at dispatch/resume. An existing owned TASK binding rejects omitted selections and metadata stripping; genuine legacy capsules keep their previous contract. Missing copies require a fresh preparation, never a silent rebind. Planning-only constructor tasks require read-only scope and produce M1 proposals, not automatic creation. Unknown external capability requests block explicitly.

`memory_mode` defaults to `inherit`, including capsules without the field. Explicit `disabled` is supported only for new service-owned chats or the same owned capsule’s resume: first native start/resume sets memory use and generation false; `thread/memoryMode/set` must acknowledge disabled before the first turn. Exact current native memory-root reads are denied for that task. An adopted user chat rejects disabled before connection/resume. Global preferences and native home stay unchanged. The schema exposes no independent mode getter: acknowledgement is not proof of cold execution. Failed, unsupported or unknown acknowledgement blocks the turn and retains the known thread identity for reconciliation; it is never automatically replayed. See [the evidence and recovery contract](../../../docs/evolution/2026-11-10/REAL-WORLD.en.md).

`task.dispatch {task_id}` atomically reserves task/project/thread before awaits and rechecks pins/authority before the turn. Raw thread overrides are rejected. `task.continue {task_id}` resumes the same bounded interrupted task with current pin checks; unknown outcomes require reconciliation. `task.pause {task_id}` persists pause and requests owned-turn interrupt. `job.interrupt/reconcile {job_id}` correlate exact thread/turn. Interrupt is pending until terminal evidence; disconnect/restart becomes `outcome_unknown` without replay. `job.review {job_id,verdict:'accepted'|'rework',note}` is owner review, not independent QA.

Existing chats: `thread.preview {thread_id}` checks exact ID/cwd/status; `thread.adopt {preview_id,confirmed_idle_handoff:true}` accepts idle/not-loaded state and creates an expiring manual binding. Other desktop clients are not fenced. Do not run the same chat concurrently in both interfaces.

`approval.respond {job_id,request_id,decision:'decline'|'cancel'}` rejects expired/cross-job/wrong-turn requests. Requests expose `can_accept`; scope expansion cannot be accepted under a narrower task. No session/policy amendment. Actual questions use `decision:{answers:{...}}` for the correlated request.

`codex.connect {}` initializes the public app-server, inspects sanitized public account mode, disables ambient MCP/apps and imports actual `skills/list`; `codex.skills {}` refreshes discovery. No private DB writes/auth-file scraping. Dispatch requires confirmed existing ChatGPT access; unknown/API billing is not treated as free. Default jobs deny shell network, web search and ambient MCP/apps. Explicit `public_web_read` requests supported public search without granting arbitrary API/shell effects. Unavailable tools require a capable reviewed host. Profiles protect native metadata, unrelated HOME/tmp, private service data and credential filenames. The installed CLI cannot represent literal extra read-grant paths containing glob metacharacters; such custom data/snapshot paths fail explicitly.

Catalog distinguishes core 33, optional sources, actual host-discovered skills and role configuration metadata. Presence is not execution evidence. Vendor/plugin caches and role files are read-only.

`skills.audit/update-plan {installed_root?}` returns the exact native plan ID/digest/report; `skills.diff {plan_id}`; `skills.apply {plan_id,plan_sha256,confirmed:true}`; `skills.verify {journal_id?}`; `skills.rollback {journal_id,confirmed:true}`. Fixed-argument native updater operations manage only the core suite. Exact updater target/journal checks are authoritative. WORK is deferred separately.

`service.settings {locale}`; `service.backup {}` → `{backup_id,sha256}`; `service.restore-preview {backup_id}`; `service.restore {backup_id,sha256,confirmed:true}` requires a current preview, idle/reconciled jobs and synchronous maintenance barrier. The backup is STORE-JSON metadata only: it excludes selected-skill file payloads, private archives and separate execution copies. Preserve private filesystem copies separately for a complete local update backup. Restore covers service records, preserves newer command receipts and invalidates old task/handoff authority; it does not restore native projects or independent Codex chats. `service.status/doctor {}` reads status; `service.stop {}` drains the owned instance.

`decision.record`/`evidence.register` use service-owned task/job review subjects, not unsupported native schemas. Evidence requires current pins and real source; author declarations do not certify independence. Known credential patterns are redacted before durable job/event/receipt storage; arbitrary-secret detection is not claimed. Source, observed execution, owner review and independent QA remain distinct.

Retention: bootstrap exposes `retention` and `pending_cleanup` receipts. `service.retention {}` reads the policy; `{policy:{event_days,history_days,input_cache_days,backup_days,automatic:false},confirmed:true}` sets each duration to 1–3650 days or null. No automatic TTL is claimed. `service.cleanup-preview {forget_project_ids?:[],forget_job_ids?:[]}` returns exact `{preview_id,sha256,policy,counts,scope}`. `service.cleanup-apply {preview_id,sha256,confirmed:true}` requires idle/reconciled work and a synchronous maintenance barrier; `service.cleanup-resume {cleanup_id}` resumes a recorded interrupted file-cleanup phase. Native projects/provider data remain untouched. Newest two service backups are preserved under backup retention; logical tombstones prevent forgotten history being revived by service restore. Cleanup also derives and validates each owned execution-input task subtree from the actual data directory and task identity; arbitrary external journal paths, unknown members and replaced ownership block deletion. Cleanup is not secure physical erasure.

## Native portfolio and universal entry (0.2)

`GET /api/v1/portfolio` returns the current in-memory discovery snapshot. `portfolio.refresh {include_archived?:boolean,max_pages?:1..50}` reads public native `thread/list` pages, explicitly includes all supported source kinds, and uses `useStateDbOnly:true`; it does not scan HOME or directly read/modify a native database. Active and archived listings have separate cursors. A dedicated public-read connection uses the native app-server history index: the execution adapter's isolated `sqlite_home` does not contain existing paginated turn history. Its private transport allows only initialization, non-refreshing account metadata, state-db-only thread listing, metadata-only thread read, bounded full-item/metadata turn pages and bounded public `thread/items/list` pages; every mutation is denied at RPC admission. Execution remains on the separate isolated adapter. Discovery groups canonical cwd roots and joins already-bound projects. It does not bind, adopt, migrate or grant writing to a discovered project.

The snapshot has `{status,checked_at,coverage,summary,projects,warnings}`. Each project has a stable discovery `id`, `root`, optional `binding_id`, native session count, phase, goal, declared next actions, agent source availability, known-work group counts and warnings. `coverage.complete/truncated/pages` describe the actual bounded listing. Registered empty projects are **not** claimed: CLI history is not the desktop project registry. Missing/private roots remain visible as unavailable metadata; private service/account root contents are not imported. Discovery caches are ephemeral and revoked by privacy cleanup or restore.

`GET /api/v1/portfolio/projects/:discovery_id?max_threads=40&max_turn_pages=4&thread_offset=0&snapshot_checked_at=...` reads one bounded page of the selected project's work map. Bounds are 1–100 threads per project page and 1–20 pages of 50 turn records per thread; native item-content coverage is paginated separately as described below. `coverage.next_thread_offset` exposes remaining project-thread pages; nonzero offsets require the unchanged discovery `snapshot_checked_at` token. `threads` contains only the requested page. The client loads every next page in order, merges work by native thread/turn identity (falling back to item ID for unpaired records), deduplicates repeated source records and warnings, and rejects project/source/inventory drift. Project change or discovery refresh resets the accumulated work map. The response is `{project,threads,work_groups,goal,next_actions,agents,coverage,warnings,checked_at}`. Every native work item retains thread/turn provenance, observed response, file-change/command evidence references and selected-versus-mentioned skills. A completed native turn is `answer_received` only when an actual nonempty agent response was observed; a completed user-only or unloaded turn stays `recorded` with a coverage warning. A response is not accepted product work. Explicit native task records and service jobs retain their separate origin; correlated service/native turns are joined. Remaining cursors, unavailable items and limits make coverage partial rather than silently complete. Listed thread metadata with an empty persisted turn page yields `NATIVE_HISTORY_EMPTY` and incomplete coverage; zero returned turns do not prove zero prior work. Coverage includes `turns_observed`, `empty_history_threads`, `threads_read` and `threads_attempted`. `page_complete` describes actual warnings and turn coverage on one page independently of remaining project-thread pages; overall `complete` requires all discovered project-thread pages, complete native turn coverage and complete discovery. A remaining native turn cursor yields `NATIVE_TURN_PAGE_LIMIT`; it cannot be cleared by loading additional thread pages. Matching native/service work retains the native ID, service job linkage, explicit owner review and combined evidence across pages. Lazy reads update ephemeral global known-work counts and loaded-project group counts by canonical work identity; unloaded projects retain source-only/unknown history labels. Refresh and privacy invalidation clear these observed page counts, while detail reads preserve the discovery token. Existing chat execution still requires exact idle preview/adoption.

Project projections read known native formats plus bounded project-owned checkpoint/passport documents under `docs/project`, `docs/agent` and `docs/requirements`. App singular `requirement`, `decision`, `job` groups are retained. Nested Foundry blueprint goals are read. `goal.status=accepted` requires the observed exact current blueprint approval and pinned canonical user authority record; a document title, Markdown phrase or unpinned approval flag stays `declared`/`unknown`. Installed project skill source presence and actual host discovery are separate. Names come only from initial SKILL frontmatter; observed agent sources are included in project revision pins. A recorded root replaced by a link stays unavailable until its identity is reviewed explicitly. `project.preview {root,source_refs?:relativeFiles[]}` supports up to 40 explicit additional native sources; the reviewed locators persist with the binding, and escapes/links are rejected.

Large native histories use `thread/turns/list(itemsView:"notLoaded")` for metadata and descending `thread/items/list` pages for actual content. The existing full-turn adapter remains a fallback for older hosts/custom adapters without item paging. Per selected thread, one request reads at most `max_turn_pages*2` successful item pages of 50 items, with at most six additional attempts to shrink an oversized page down to one item. The 8 MiB transport cap remains unchanged. An oversized single item, repeated/invalid cursor, missing identity, metadata gap or missing answer is reported as a coverage gap. A bounded page never certifies content it did not read. `coverage.item_pages/history_item_requests/history_items_observed` expose actual reads; `coverage.limits` exposes the bounds. `coverage.non_item_page_complete` excludes only a pending recoverable item cursor, preserving unrelated empty/access/protocol/turn-metadata/answer gaps.

`GET /api/v1/portfolio/projects/:id?item_thread_id=...&item_cursor=...&snapshot_checked_at=...` continues a returned `coverage.item_cursors` entry. Entries contain `{thread_id,next_cursor,pages,items_observed,limit,items_complete,thread_offset}`; terminal entries retain `next_cursor:null`. The exact cursor is admitted only for its observed project/thread/discovery generation/native source revision, including a thread originally loaded on a later outer page. Refresh, privacy invalidation, source drift or an already-consumed cursor requires a fresh history page. A continuation returns only that thread's next observed slice plus current source/service work, and declares `coverage.item_continuation/item_thread_id/consumed_item_cursor`; outer-page locators remain associated with the original page. The client merges by native thread/turn identity, retains a newer actual response across older descending slices, fills a missing original objective, joins evidence/skills and preserves unrelated pages and gaps. `objective_observed` and `response_item_id` distinguish actual observed content from a metadata title. Pending cursors remain actionable in the interface; a terminal item stream is separate from complete turn metadata, original context or accepted product work. The server retains only bounded work projections and minimal cursor/answer-ID admission state, not a second raw-history store.

An optional project-owned `.atelier/context-bindings.json` (or one explicitly selected JSON source) with `schema:"atelier.context-bindings/1"` binds `project_root` to the exact canonical selected root. `sources` contains 1–40 `{path,sha256,role,required?:boolean,requirement_ids?:string[]}` records; paths stay normalized, relative, inside the existing artifact scope and free of links. Required defaults to true. `expected_requirement_ids` and `expected_must_ids` independently name obligations expected in the native register; every native applicable must remains included even when absent from those lists. A source's `requirement_ids` must be observed as parsed native rows from that exact file. Roles `requirements`/`decisions` require supported structured native groups; other roles pin sources without inventing a semantic projection. Optional `requirement_links:[{requirement_id,source_path,source_excerpt}]` checks that a literal excerpt occurs in both its pinned original and the corresponding native verbatim text. This detects a lost declared quote, not all omitted meaning. Requirement IDs/lists are bounded to 240 characters/2000 entries; excerpts to 20000 characters. Workspace and capsule expose `context_coverage` (also `workspace.context.coverage`) with source/excerpt checks, missing requirements/musts and blocking issues. Required drift, wrong project, missing originals, unsupported declared projection or unresolved correction conflicts block preparation; the workspace remains readable. Without a binding, existing projects retain their behavior and coverage is explicitly `unverified`. A successful binding is only `verified-declared-bindings`; `source_completeness_authenticated` remains false. The original native records and actual owner authority remain authoritative.

Native decision records may explicitly declare `supersedes:string[]` with unique decision IDs. The service retains every raw decision and source hash, adds `corrections`, and projects the unsuperseded records in `current_decisions`; it never infers supersession from a timestamp, title or summary. Missing/ambiguous predecessors and cycles retain all decisions and expose a conflict (blocking when a binding is declared; legacy projections remain usable with a warning). Native `deferred_work`/`deferred` records are retained separately with source hashes. These additive fields also enter prepared capsules; they grant no authority, acceptance or additional tool scope.

`task.route {objective,route?,intent?:'auto',acceptance?,scope?,allowed_paths?,creation_scope?,maintenance?}` with `project_id` returns `{routing}`. Routes are `direct|specialist|project_agent|director|compose|create_agent|maintain_system|bridge`. The result is a proposal, not a performed invocation or new permission. Automatic routing remains `null` until the actual orchestration skill evaluates the request, except one unambiguous installed and host-discovered project agent can be proposed from verified source context. Its normalized source path and current SHA must both match the observed project source. Declared agents and every installed origin remain separate; multiple executable sources require an explicit source choice instead of selecting the first slug. The service does not call a keyword classifier an expert decision.

`task.prepare` adds optional `universal_entry:true`, the same route inputs and optional reviewed `routing_sha256`. It refreshes current-project skill discovery, requires an enabled installed orchestrator matching the canonical release, includes that verified source snapshot and preserves the original result acceptance, creation/execution scopes, maintenance target and continuation owner in the capsule. The normal four-skill bound, exact source/instruction pins, deadline, private-path controls, native writer handoff and explicit dispatch remain in force. It never silently converts approved construction plus execution into planning only.

Maintenance metadata is `{target_kind:'orchestrator'|'skill'|'constructor'|'project_agent'|'agent'|'system',target_refs:string[]}`. Targets are stable selectors or paths within the selected canonical project; they do not authorize self-approval, global account changes, installation or an external effect. Native state construction uses a separately reviewed controller operation rather than widened model filesystem permissions.

`controller.preview {controller:'foundry',operation,session_path?,params?,record_path?}` with `project_id` returns a reviewed exact native operation, source/state/input hashes, proposed argv, applicable authority subject and `preview_id/sha256`. `controller.apply {preview_id,sha256,confirmed:true}` executes only that fixed trusted native controller with original native validation and a state comparison inside its native exclusive lock. Before-state backups and actual pending/terminal receipts are service-owned. It does not run a model, provider, deployment or product runtime. `controller.reconcile {receipt_id}` reads the current native state; `{receipt_id,sha256,confirmed:true}` records owner-reviewed reconciliation without automatic replay. Native child filesystem permissions stay unchanged.

`skills.optional-preview {name}` supports only known optional orchestration/maintenance sources. It returns exact source/installed-tree hashes, changes, preservation checks, conflicts and a preview. `skills.optional-apply {preview_id,sha256,confirmed:true}` updates only the ready reviewed source with before/after snapshots and per-file progress; unknown/customized source conflicts remain blocked. `skills.optional-verify {journal_id}` observes the actual full tree and reconciles an exact before/after state without repeating file writes. `skills.optional-rollback {journal_id,current_sha256,confirmed:true}` restores only a reviewed managed before-copy if current bytes still belong to that operation; newer unknown work is preserved. Refresh `codex.skills` after source maintenance: installed bytes are not host discovery.

Bootstrap exposes `native_controllers` and compact `optional_updates` receipts (`id,name,status,started_at,completed_at`). Pending operations become `outcome_unknown` after restart. Overlapping native-controller uncertainty blocks task dispatch; optional-source uncertainty blocks dispatch globally because tasks consume shared installed skills. New maintenance, cleanup, backup and restore require reconciled work. Explicit receipt-only native reconciliation and the updater's verified own rollback provide recovery without reopening a deadlock; neither grants a new product effect. Restore invalidates pending operation authority and preserves unknown outcomes for reconciliation.

`service.diagnostic-preview {}` returns reviewable aggregate `{preview_id,sha256,data,scope}` omitting project paths, task text, account/chat IDs, source/output and credentials. `service.diagnostic-export {preview_id,sha256,confirmed:true}` writes only that approved JSON in private local `exports/` and returns its content. No external transmission occurs.

Writer reservations compare canonical project-root containment, not only project IDs. Overlapping ancestor/descendant roots share the mutation boundary, including unknown or legacy jobs. Overlapping readers share the two-reader bound; disjoint projects retain concurrency.

Workspace-write admission also protects nested native authority directories. Writable paths cannot name a native authority directory directly. Before start/resume and each turn, the adapter inventories the allowed subtrees and compares the protected-path/root identities. Scoped absolute deny patterns protect existing and future native directory names, while exact existing read exceptions retain native source access. This includes case variants and escaped metacharacters in the selected root. The inventory never follows links and fails closed beyond 200000 entries or 128 levels, or for an unsupported literal grant/protected path; choose a narrower artifact directory rather than broadening the sandbox. A changed inventory blocks the next turn. This check is not an atomic fence against an independent external writer, and a tested CLI/OS policy is not proof for another parser or platform. Native mutations still use the reviewed controller path.

The current workspace goal, declared next actions and installed-agent sources are read from the freshly inspected workspace. A separately paged portfolio snapshot cannot replace those fields with an older goal or action. An empty/unknown current goal remains unknown; a declared goal is not upgraded to accepted.

Native history preserves sanitized structured source, `thread_source` and `parent_thread_id`. Exact native Guardian markers classify a record as `work_type: permission_review`; these records remain observable in `system_checks`, separate from user-result lanes. Their original native status/response facts and provenance remain intact; they do not establish a product result, owner approval or independent QA. Titles or answer wording never supply that classification.
