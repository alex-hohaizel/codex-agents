# Game Atelier LiveOps

## Scope and current evidence

Use the caller's language, then the project preference, then Ukrainian. Work from current project-owned requirements, accepted originals, decision history, checkpoint, applicable evidence, permissions, budget, and stop boundaries. Apply the [context capsule](references/context-capsule.md) and [adaptive work](references/adaptive-work.md) on new, delegated, or resumed work. Preserve exact source and requirement IDs and every applicable accepted property. For a focused repair, understand its dependencies and read the affected contracts. Scale research, team, and verification to the actual risk and breadth.

For **BRIEF (БРИФ)** or **RESUME (ВІДНОВИ)**, follow the [briefing protocol](references/briefing-protocol.md), with the [topics](assets/briefing-topics.json) and [domain guide](references/briefing-domain-guide.md) where relevant. Reconcile current sources and runtime before resuming. Reuse exact authority, ask only about unresolved material decisions, and honor the existing pause. Close a stage with the deliverable, due evidence, remaining gaps, and the next action or decision. Separate the full target, first release, and representative slice.

Before making or changing material, apply [production quality](references/production-quality.md) and the relevant profile in `assets/production-profiles.json`. Keep reference composition, scale, interaction, and functional depth. Demonstrate a representative slice on the actual medium before scaling a dependent batch. Use the relevant [AI and data workflow](references/ai-production.md) for applicable data, retrieval, model, media, or evaluation work. Seek an evidenced need before adding infrastructure. Keep original data, rights, and creative identity in their native sources. Discuss material deviations with the owner and retain current visual identity using the [visual identity contract](references/visual-identity.md).

Give each artifact one owner and use independent reviewers for the checks the stage requires. Use [research and synthesis](references/research-and-synthesis.md) for consequential unfamiliar decisions. Consult the [interaction protocol](references/interaction-protocol.md) for status or handoff. A structural helper validates records. Record separate observations for craft, function, source, native or device execution, independent review, and owner acceptance. Keep due blocked evidence visible. After two attempts with the same failure, change the diagnosis.

Use [Work and Codex continuity](references/joint-work-codex.md) for authorized cross-host recovery and transfer. Give exact inputs, capabilities, steps, expected receipt, and return verification. Apply [tool compatibility](references/tool-compatibility.md) to the actual operation, target, rights, and costs. Reconcile unknown effects before retrying. For batches report the denominator and separate completed, blocked, skipped, and failed entries. Test self-updates on comparable inputs, preserve the known predecessor, and verify recovery.

Use one versioned Game Model and the current game workflow and handoff contracts. Keep the distinct maturity gates C0 labelled exploration, C1 complete candidate concept, and T production design. A bounded early spike has a question, precise inputs, an oracle, and a stop. It supplies evidence for that question. Cover every applicable production domain and assign due proof. Separate game maturity from implementation, native build, and distribution status. Keep legacy sources unchanged and reconstruct the current projection from accepted source facts, using the supported current format and explicit mappings. Check installed capabilities for the operation; host names alone give no tool, runtime, or device proof.

## Reconcile the observed runtime and round

Use the [LiveOps playbook](references/liveops-playbook.md), [forms](assets/liveops-templates.md), and [diagnostic catalog](assets/liveops-question-catalog.json). Pin release handoff, actual build/store/client environment, config and flags, content, progression, economy, save, entitlement, acquisition, event schema and experiment versions. Record current player time window, timezone, platform/region/cohorts, observer, exact inputs, affected scope and stop. Verify provider read-back or name the actual source gap. Distinguish incident, diagnosis, content, deterministic repair, bounded experiment and cost audit. Read-only analysis and already authorized rehearsal have their own scope.

For each claim bind query/export digest, counts, numerator and denominator, inclusion/exclusion, assigned and exposed populations, cohort/platform/build/config mix, event definitions, uncertainty, causality and decision impact. Validate clock skew, schema drift, loss, duplicate/offline events and special traffic. Support reviews and volunteers are signals with selection limits. An intention to return and simulated patience are different from measured retention. When v1 and v2 observe different actions or cohorts are unmatched, hold promotion, reconcile event semantics or remeasure. Compare like-for-like guardrails, same eligibility and time window, explicit config and rollback impact. Passing a small matched comparison can justify holding an already admitted reversible rollout while gathering more data. It does not justify claims unsupported by the sample.

## Diagnose causes across the actual product

Inspect the player journey and first meaningful action, independent learning/transfer, retry/re-entry and productive next goals. Examine decision variety, AI/encounter/world/route and consequence, build and mastery, unlock plus actual old-task use, reward and economy, content repetition, spending limits/complaints/refunds/fairness. Retain player budget, meaningful baseline, correct paid information, accessible state and existing creative intent. Distinguish paths by behavior. Check actual incidents, crashes, saves, input/camera, missed haptics and audio, thermal and content budget, payment integrity and recovery. Use actual platform and device reports where due. Record causal damage and continuity traces, capability-by-opportunity and actual production attempts. Setup, explanation, and reproducible defect evidence are separate.

## Change and recover in the approved scope

Write the causal hypothesis, affected IDs and player context, expected observable decision, bounded cost and exposure, applicable design/runtime/native/store/player and independent QA evidence, and explicit guardrails/stop. An experiment requires assignment, sticky unit, exposure, meaningful metric, necessary data/cost, sample, duration and honest uncertainty. Use the simpler deterministic repair where appropriate. Respect source and consent and do not invent participants or collect unnecessary personal data. Apply exact dependencies for code and content or send affected work through Build, QA and Release.

Use versioned compatible migration, config and catalog ownership, preserve earned progress and verified entitlements, idempotent/interruptible changes and actual rollback/recovery. Record release scope and owner, evidence before change, updated state and receipts, budget, stop, guardrail and rollback. Distinguish halt, narrow flag disable, config/backend rollback, and forward binary hotfix. Check active old clients and the economy after rollback. Reconcile unknown external outcomes before further changes. For incidents send external communication only when authorized. Use an actual scheduler, verified permissions, cost/privacy and stop only for a requested recurring operation.

Deliver exact source/build/config/economy and event evidence, causal findings and honest hypotheses, affected requirements, verified result, operations and support handoff, costs, known gaps, next owner and checkpoint. Inspect actual Game Model, Atelier and pipeline flags before running them and retain verified unaffected evidence.
