# Liveops: спостереження й керовані зміни 4.0

## Відновити реальний стан

Прийняти immutable release identity, source/build/config/catalog/content/economy/save/experiment versions, actual providers/alerts/incidents/support/rights, accepted model й current access. Читати exact released state; локальний latest checkout або поточний template не доводить production. Окремо фіксувати що реально спостерігається й що лише заплановано.

## Bounded цикл

1. Визначити incident/diagnosis/content/experiment/cost scope, cohort/platform/build/window/stop, чинні дозволи й resource cap. Нові production writes, paid services чи regions мають конкретний project decision.
2. Перевірити quality телеметрії: версії, eligible numerator/denominator, duplicates/lost/offline events/clock skew, mix/assignment/privacy. Невідоме не заповнювати вигаданими industry benchmarks.
3. Пов’язати observed failure із player information→available response→input/AI→contact/resolver→outcome→durable save→return. Відрізняти design difficulty, misrecognition, execution mistake, performance й defect; не «ремонтувати» все прихованим DDA.
4. Аналізувати можливість×нагода, learning/exposure/transfer/reorientation, world/AI/boss/route variation, reward/use/exhaustion, cumulative paid portfolio й економічні хвости. Pick rate сам не доводить dominance; average DPS не доводить actual TTK/fairness.
5. Для зміни створити exact affectedIDs/dependencies/expected decision, numeric/state/content contracts, production recipes й native/data compatibility. Оновлення grip/damage зачіпає relevant control/camera/world/generation/AI/economy/save/learning/craft; unrelated studio originals не переглядати.
6. Перевірити model/oracle→staging/runtime→належний sandbox/device/human layer→independent QA→authorized release. Сам report або simulation не означає фактичного покращення cohort metrics.
7. Зберегти actual action/receipt/result, невизначеності, права/прогрес та exact next route. Коли дія завершена — checkpoint і очікування нового доручення; recurring round лише через actual scheduler за окремим scope.

## Критичні перетини

| Зміна/інцидент | Що перевірити разом |
|---|---|
| Damage/boss balance | Units/order/capture/DoT/RNG, lifecycle priorities, readable cues, paid/earned builds, opportunity/TTK tails, historical fixture conformance |
| Death/crash/retry | Reason/recovery, kept/lost costs, simultaneous outcomes/reward once, input/transform reset, durable consistency й no-softlock |
| Save/cloud/support | Exact profile/account/revision, old/new schema, two offline branches, tombstone, consumed grants/refunds, quota/clock/precision; не reset progress |
| Content/generator | Macro progression/legality/novelty, prerequisite counters, lore/topology/nav, atomic epoch, compatible old client й fallback |
| Asset/audio/tool update | Source/rights/provenance, semantic cache invalidation, import lint, source roundtrip, contact/loop/cue/assembly/device parity |
| SDK/backend/service | Native conformance, actual data egress, budgets/rate/cost/failure/restore, sunset/offboarding за fit |
| Patch/release | Exact base bytes/hash, symbol match, staged activation/halt/forward fix; binary rollback не миттєвий |

## Diagnostics і repair

Використати scenario lab для setup, reason inspector для поточного рішення, repro capsule для sanitized повтору. Це різні функції. Production attempts містять actual input/toolchain/job/output/cost/status; unknown outcome reconcile, не повторювати платну генерацію чи deployment наосліп.

Для causal repair визначити source ambiguity/capability mismatch/production defect/integration/QA/runtime cause. Два однакові невдалі повтори → новий метод/owner; відсутній rig/SDK не лікується загальними prompts. Змінені importer/model/recipe/config інвалідують лише залежні докази; approved original лишається незмінним.

## Вихід

Надати findings із current sources/queries/timewindow/denominator/uncertainty, reproduced scenarios, exact patches/receipts/verification, revised model/recipe/evidence refs, player-visible effects й unresolved owners. Не називати покращення доведеним без відповідного live observation; не заявляти self-improvement у фоні. Наступне звернення почати зі звірки released reality, а не припущення, що чекпойнт досі актуальний.
