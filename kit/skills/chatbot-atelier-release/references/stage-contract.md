# Stage contract for chatbot-atelier-release

## Visible result and applicability

Determine the task scope and a sufficient method using [adaptive work](adaptive-work.md). Apply [focused research and synthesis](research-and-synthesis.md) at any stage when it is relevant. The agreed project profile defines active functions, platforms and persona. Preserve established IDs, permissions, accepted results and full intent. Bind reviews to the exact observed source and version. A local repair uses the affected route and its applicable acceptance requirements.

Show readiness for the exact artifact, current authorization, impact on existing jobs, state and data, rollback or compensation checks and actual receipts. Keep skill installation separate from project migration and product release.

## Prepare the exact authorized release

Check platform/service/environment/account, pinned source/build/assets, required tests on the exact candidate, independent QA, schema and ownership, secrets separation, privacy/retention/tombstones, quotas/cost, rollout, stop and recovery. Do authorized reversible preparation first. Apply existing exact authority without another confirmation. Verify current provider docs, schema, SDK and installed commands. Release tests, green CI and old runbooks are separate from deployed health, actual delivery, and naturalness. Treat new targets or paid resources as separately scoped.

## Verify compatibility and one active writer

Retain pending jobs, buttons and semantic versions, data/migrations, model/tool contracts, privacy epochs/tombstones, approved media fingerprints, and deduplication. In an isolated environment rehearse stage, prior callback, rollback and replay with persistent state readback. Preserve one effect and existing jobs. Verify only one dispatcher can write during a transition, and block promotion when an older runtime cannot read preserved receipts or fields. Test backup/restore without reviving erased data. For forward-only change, state the actual compensation path.

Record actual deploy/publication ID and exact source/build/hash. Poll existing jobs. Reconcile unknown provider outcomes through status/readback before considering a retry. Observe health/version/logs and test the actual requested platform behavior and media membership/readback when applicable. Keep send acceptance, human read and satisfaction distinct.

## Pass current evidence to operations

Record target, source, build, deployment, time/environment, tests, health, delivery and rollback, including partial and failed outcomes. List support ownership, recovery/export/retention, unresolved jobs/retries, SLI/alerts, provider state and migration policy. If the live boundary is unavailable, report the exact locally verified scope and next step. Operate recurring automation only when separately requested and verified.

## Handoff

Provide stage ID, requirement and source IDs, exact versions and hashes, applicability and reason, typed rules, states and cross-system dependencies, capabilities and authority, operation contracts, recipes and effective parameters, actual attempts and job IDs, outputs and consumers, evidence and limits, negative cases, unresolved items, receiving owner and next acceptance check. The receiver can verify the finding without chat history. Return incompatible input or an infeasible requirement to the appropriate upstream owner.

## Criteria and completion

Check applicability for these criterion IDs first: version_continuity, audience_privacy, forgetting_integrity, media_delivery, execution_truth, provider_constraints. Use all 24 baseline IDs for the impact map. Record active, carried or out of scope with reasons based on the current profile and accepted scope. Retain all approved requirements. For each active requirement record an owner, artifact, positive and negative checks, evidence kind, verdict, strongest objection and limits. Unknown evidence for a critical claim blocks the affected readiness. The author and independent QA are distinct. Human or production verification requires the actual applicable observation.

Deliver the complete requested result. Track concept, specification, production handoff, integration, live observation and human evaluation independently. When two attempts yield no new evidence, change the diagnostic hypothesis. A depleted budget leaves unmet acceptance criteria visible.
