# ChatBot Atelier · Release

## Prepare the exact authorized release

Check platform/service/environment/account, pinned source/build/assets, required tests on the exact candidate, independent QA, schema and ownership, secrets separation, privacy/retention/tombstones, quotas/cost, rollout, stop and recovery. Do authorized reversible preparation first. Apply existing exact authority without another confirmation. Verify current provider docs, schema, SDK and installed commands. Release tests, green CI and old runbooks are separate from deployed health, actual delivery, and naturalness. Treat new targets or paid resources as separately scoped.

## Verify compatibility and one active writer

Retain pending jobs, buttons and semantic versions, data/migrations, model/tool contracts, privacy epochs/tombstones, approved media fingerprints, and deduplication. In an isolated environment rehearse stage, prior callback, rollback and replay with persistent state readback. Preserve one effect and existing jobs. Verify only one dispatcher can write during a transition, and block promotion when an older runtime cannot read preserved receipts or fields. Test backup/restore without reviving erased data. For forward-only change, state the actual compensation path.

Record actual deploy/publication ID and exact source/build/hash. Poll existing jobs. Reconcile unknown provider outcomes through status/readback before considering a retry. Observe health/version/logs and test the actual requested platform behavior and media membership/readback when applicable. Keep send acceptance, human read and satisfaction distinct.

## Pass current evidence to operations

Record target, source, build, deployment, time/environment, tests, health, delivery and rollback, including partial and failed outcomes. List support ownership, recovery/export/retention, unresolved jobs/retries, SLI/alerts, provider state and migration policy. If the live boundary is unavailable, report the exact locally verified scope and next step. Operate recurring automation only when separately requested and verified.

## Shared rules and reference lookup

Use the user's requested output language, then the applicable project preference, then the request language. Keep quoted text, commands, identifiers, and native names intact. Restore the source, checkpoint, intended result, work in progress, exact capabilities and allowed effects before changing them. Preserve the applicable musts, dependencies, identities and pending/deferred work in the current project registry. A single owner integrates. Use sufficient scope and depth for the task. Keep small repairs focused and a full product brief complete.

Read the [context capsule](references/context-capsule.md), [adaptive workflow](references/adaptive-work.md), and [research and synthesis guidance](references/research-and-synthesis.md) as needed for the task, its source pins, budget, receiver and acceptance. Use `scripts/context_capsule.py` and `scripts/adaptive_work.py` for declared data checks. Verify unfamiliar domain and tools against primary sources and small relevant probes. For a new agent, carry work from analysis and approved architecture through a portable package, independent representative tasks, installation/discovery and support. Keep accepted [visual identity](references/visual-identity.md), icons and colors. Verify changed hosts with the relevant smoke test or record a blocked check.

For visual, media or other material production, use the [production quality contract](references/production-quality.md) and `assets/production-profiles.json`. Preserve the accepted reference's scale, composition, visual mechanism, interaction and functional depth. Verify a representative result in its actual medium before producing a batch. For data acquisition/analysis, LLM/retrieval, prediction, model adaptation, media or evaluation, use only the applicable [AI and data profiles](references/ai-production.md). Use existing owners and sufficient tools first. `scripts/ai_production.py` validates declared inputs; verify actual results in their consumers.

Use the [interaction protocol](references/interaction-protocol.md) for meaningful choices, progress and handoff. `python3 -B scripts/interaction.py status --source PROJECT --format markdown` reads supported domain state. Verify channel/target, supported schema, permissions and limits with [tool compatibility](references/tool-compatibility.md) and the [joint Work and Codex route](references/joint-work-codex.md). Report a missing required tool or provider as an open gap. When an effect's response is lost, reconcile the target before retry. After two attempts without new evidence, change the hypothesis or stop the affected work. No polling or background work is assumed.

For BRIEF (БРИФ), RESUME (ВІДНОВИ), or a material scope change, consult the [briefing protocol](references/briefing-protocol.md), [stage briefing topics](assets/briefing-topics.json) and [domain guide](references/briefing-domain-guide.md). Resume by reconciling original intent, current sources, decisions, evidence, runtime and unfinished work. Retain pause, authority and dependency limits. Assess the applicable scope, ask targeted questions, record a versioned proposal and exact decisions, then execute the authorized work. Distinguish full target, first release and representative slice. Reuse a valid prior approval. Ask for a new brief only when a material decision changes. `scripts/briefing.py` checks bindings. A terminal result ends the approved task.

## Channels, contracts, and handoff

For an existing bot, inspect the [current project route](references/resume-current-project.md). Current source and goal are enough to resume; an older agent package is optional. Recover accepted platforms from repository/config and decisions. For a new bot, select the channel from the task, live capabilities and access. Use [platform adapters](references/platform-adapters.md) and [primary platform sources](references/platform-sources.md) for changes. Confirm MCP/API/connector availability for each needed operation. `chatbot.blueprint/3` binds `platform_adapters` and each journey's `adapter_ids`. Use supported [protocol formats](references/protocols.md) and require an explicit adapter for older unsupported formats. Check declared adapters and rounds with `python3 scripts/check_platform_adapter.py ADAPTER.json` and `python3 scripts/check_round.py ROUND.json`.

For a product component use the [component handoff](assets/component-handoff.template.json) and `python3 scripts/check_component_handoff.py HANDOFF.json --root PROJECT_DIR`. Preserve the parent authority, IDs, interfaces, and permissions. Find actual `agent-foundry`, `app-atelier-director` or ChatBot siblings by stable name and current source. Use the [cross-domain contract](references/cross-domain-core.md), [stage contract](references/stage-contract.md), [lifecycle and team](references/lifecycle-and-team.md), [domain contracts](references/domain-contracts.md), [production recipes](references/production-recipes.md), [quality and operations](references/quality-and-operations.md), and [Work/Codex boundaries](references/work-codex.md) only for relevant decisions. Map requirement → formal rule → operation → recipe → attempt → integrated user journey → evidence.

Map affected and unchanged [24 companion criteria](assets/requirements.json) using the [evolution domains](references/evolution-domains.md), [team policy](references/team-policy.md) and [evolution contract](references/evolution-contract.md). Keep unknown impact visible. For full rounds retain `round.json` and use `teamctl.py plan`, `hashes` and `freeze` from [evidence and delivery](references/evidence-and-delivery.md). Use the [domain model](assets/chatbot-blueprint.template.json), [action contract](assets/action-contract.template.json), [memory contract](assets/memory-contract.template.json), [operation catalog](assets/operation-catalog.json), and [evaluation matrix](assets/evaluation-matrix.json) where applicable. Run `python3 scripts/check_chat_contract.py /absolute/path/chatbot-blueprint.json` and the graph gate for active cross-system contracts.

Report exact inputs/outputs, hashes, decisions, attempts/jobs, evidence limits, receiving owner, next action and upstream return condition. Track specification, code, integration, device, human and authorized acceptance separately from actual deploy and observed-in-chat facts. Human review of historic artifacts stays bound to its original revision. A structural pass establishes the checked shape. For a large batch record the full denominator, completed/skipped/error items and checkpoint. Compare self-updates against the prior version with equal inputs, independent criteria, legacy replay/adoption tests and rollback checks.
