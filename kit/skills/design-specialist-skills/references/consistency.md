# Узгодженість створюваних навичок

До збереження кожної спеціалізації звірити SKILL.md, всі її references, assets, scripts і UI metadata. Поточні правила мають одне джерело; додаток не може повертати старий штат, інший scope, пропущене погодження або старий критерій завершення.

Назва/редакція батьківської навички не є залежністю. Для сімейства зв’язувати етапи через самодостатні входи/виходи й версійовані контракти. Номери схем і справжня історія походження залишаються технічними метаданими; явно відділити їх від чинних інструкцій. Не підміняти факти походження новим номером.

Всі локальні посилання й команди мають існувати в цьому пакеті. Перевірити CLI flags, схему контейнера, порядок hashes/freeze/review, окремі local/stage statuses та відповідність живому валідатору. Не копіювати блок команд сусідньої навички або залежати від її локального шляху.

Повнота критеріїв не задає кількість агентів. Зберегти потрібні компетенції, незалежність та actual modalities; усунути суперечливі вимоги до fixed суддів або менеджерів. Зміни спільної залежності й критичні дії зберігають потрібне приймання.

За оновлення старої навички перевірити всі пов’язані файли, а не лише новий заголовок. Додати пропорційний regression check для знайденого класу розбіжностей. Якщо використовуються машинні контракти, синхронно оновити їхні defaults/help/registry та правила сумісності; старі первинні підписи не переписувати.

У bundled check_consistency.py перевіряються локальні ресурси, поточні команди, версійні згадки та незмінність предметного покриття. Для створюваної навички застосувати ці правила з її власним consistency contract; проста однофайлова навичка може пройти еквівалентну пряму перевірку без зайвих скриптів.
