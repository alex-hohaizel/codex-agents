# Consistency of generated skills

Before saving a specialization, reconcile its SKILL.md, references, assets, scripts, and UI metadata. Maintain one current rule source and check each appendix for stale team structure, scope, approval gates, and completion criteria.

Use self-contained inputs and outputs and versioned contracts between phases of a family. A parent skill name or edition identifies provenance. Technical metadata records actual schema versions and lineage independently of the current instructions. Retain authentic source facts across releases.

Check that local links and executable commands resolve within the package. Verify actual CLI flags, container schema, hash, freeze and review order, separate local and stage statuses, and correspondence to the live validator. Include each required dependency explicitly.

Preserve the competence, independence and modalities needed to cover all criteria. Resolve conflicts that would create fixed reviewer or manager counts. Keep the required acceptance checks for shared dependency changes and critical operations.

When updating an existing skill, check every related file and add a proportional regression check for the class of inconsistency found. When machine contracts are involved, update defaults, help, registry and compatibility rules together. Preserve the original signed material and its provenance.

The bundled check_consistency.py checks local resources, current commands, version references and continuity of domain coverage. Use the same principles with a generated skill's own consistency contract. A straightforward single-file skill can use an equivalent direct check.
