# Work, Codex and handoff

Use the same current semantic specification across both environments. Check actual capabilities, permissions and evidence at the target. Start with a capability snapshot covering tools and connectors, executor, network, private repository, sandbox database, runtime, media and device interfaces, cost and authority. Verify specific framework, platform, server or chat access before relying on it.

Work supports discovery, current research, UX and dialogue scenarios, provided artifacts, authorized production, connector audits and code where an executor is available. Codex in a checkout supports source edits, build, tests, migrations and CI when available. Route each operation by demonstrated capability.

Handoff includes intent and requirement IDs, complete rules and primary source map, exact artifacts and hashes, architecture and alternatives, applicability and open questions, operation contracts and recipes, attempts and job IDs, evidence limits, permissions, commands, secret-free environment selectors, locks and owners, receiver, next action, acceptance and upstream return condition. The receiver can proceed without chat history. Reconcile returned code, assets or report with input snapshot and current state before merge.

Keep installed stage assets self-contained. Use optional custom roles when the current host supports them and verify policy/schema against official sources and local configuration. Stage and team contracts retain the functions of historical roles. Their source files are archived and are not part of automatic installation.

Use current formats defined in protocols.md. Restore authoritative requirements and actual repository and state without requiring an old agent dossier. Verify runtime and toolchain, tests, asset catalog and hosting for the target project. Preserve data and behavior under the project's contracts.
