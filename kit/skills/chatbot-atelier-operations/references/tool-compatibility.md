# Connected tool compatibility

Before an operation, inspect its current parameters, target, authorization and cost. Pick the relevant contract below. Product requirements, user instructions and host policy apply to the actual step. Report a conflict or missing required capability before the dependent action. A package or its instructions alone do not establish live availability.

| Operation | Required check |
| --- | --- |
| Skill display and metadata | Patch only the affected fields. Preserve the stable skill name, policy, dependencies and other metadata. Check the actual diff when a helper regenerates YAML. |
| Image generation | Use the supported built-in path or an authorized fallback. Check output collisions, cost, permissions and pending effects before dispatch. After timeout, reconcile the provider's state before repeating the operation. A local ledger does not make provider effects exactly once. |
| Visual acceptance | Inspect the delivered artifact against the applicable requirements and the real consumer. A prompt does not establish delivery or behavior. Reviews required by the task remain required even when a provider normally discourages regeneration. |
| Google Docs | Choose native create or edit for the requested outcome. Import a Word document for requested conversion, a Word source, or an explicit justified workflow. Keep read-only questions free of hidden import and export steps. |
| Sheets and Slides | Preserve the existing document identity and target. Check the repair against the actual result. Change the diagnostic approach after repeats without progress. |
| DOCX redaction | Check the helper's actual options. Verify the proposed replacement and its length on a synthetic fixture first. Check all applicable data surfaces before making a redaction claim. |
| Go review | Use the appropriate general, distributed, or fintech lead. Read narrow style references when relevant. Record baseline tooling failures separately. `gofmt` takes files or directories rather than the package pattern `./...`. |
| Go concurrency and API | Ensure cancellation reaches blocking input and output and all owned goroutines. A detached context still requires bounds, an owner, and draining. APQ needs a separate server policy to act as an allowlist. Embedding an unimplemented gRPC server does not implement new methods. Clipping a slice retains its backing array. |
| Data authorization | Check tenant, owner and object access regardless of identifier construction. Preserve the agreed isolation model. For a Supabase helper, verify actual EXECUTE grants and search path under the selected model. |
| Database constraints | Check a constraint on the exact table, schema, or OID. A name may be nonunique. Verify migrations using required roles and scenarios. |
| Heroku or Render migration | Use a redacted or names-only inventory. Fence or stop all writers for snapshot and cutover, including workers, schedulers and integrations. HTTP maintenance alone does not fence the database. |
| Redis migration | Use a supported provider import or a verified DUMP/RESTORE path with TTL, type, counts, writer controls, replay and rollback. An RDB file is not a RESP stream for `--pipe`. |
| Website and cloud release | Verify whether deployment is immediately public and identify the live data target. Preview and review do not authorize deployment. Check the exact supported staging, container and media operations before promising them. |
| Visualizations and Pages | A local visualization can explain project state. It does not become the source of project decisions or prove access to Work chat controls or background jobs. |
| Native documents and requested formats | Create, import, edit and copy are distinct operations. Preserve the intended object, structure, and editability. Verify that the actual requested PPTX, DOCX or XLSX can be delivered before promising it. |
| Supabase UPDATE and DDL | When a separate check is absent, PostgreSQL can use the policy's USING expression as WITH CHECK for UPDATE or ALL. Do not assume an owner bypass. Verify whether the actual connector requires its migration operation for DDL. Pin target and environment before a hosted mutation. |
| Queue persistence | Verify engine, version, and the consuming URL parser. Oban uses supported SQL engines. Do not substitute Redis as its queue backend. |
| Generation and identity | Provider recipes for variation or presentation yield to the accepted identity and task. Inspect the real result. Regenerate only for a concrete defect and a changed hypothesis within scope. |
| Upload or retry | After a lost upload, send, or create response, look up provider identity and current state. Keep definite rejection, unknown outcome, and confirmed success separate. |
| Deployment and monitoring | Verify active branch, remote, CI, actual auto-deploy and scope. Use workload, SLO and baseline data for thresholds. Resume the authorized operation once its required connection exists. |
| Dated provider instructions | Check current policies, credits and deadlines before applying a recommendation. Use real domain probes with structural checks. |

These guards preserve operational findings from reviewed source and probes. Check the exact native operation before applying a provider-specific rule. A missing capability remains a named dependency with a supported bridge to the intended outcome.
