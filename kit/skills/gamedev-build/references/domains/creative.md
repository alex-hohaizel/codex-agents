# Art identity, element design and feasible production

## Applicability, inputs and owned outputs

Use from the first presentable concept through store presentation and live operations. Start with the player fantasy and emotional goals, mechanics, camera and inputs, studio and IP boundaries, exact accepted masters, budget and verified tool operations. Own a distinct art direction, visual and audio production profile, per-element specification and state inventory, source-to-export-to-import lineage, and evidence for the exact parity claim. Use the [creative element template](../../assets/domain-templates/creative-element-spec.template.json). The canonical art-domain record summarizes the underlying production materials.

## Distinct art direction

Specify shape language, proportions and silhouettes, scale, materials and textures, palette and value hierarchy, lighting and shadows, composition, depth and layering, camera, typography and icons, HUD and menus, motion and contact, VFX, sound palette and music, haptic character and store expression. Each decision supports this game's fantasy, pacing and readability. For distinct directions, vary meaningful composition or production choices beyond palette changes to one preset. Preserve room for different camera styles, protagonists and material treatments within the same studio identity.

Consider appropriate 2D and sprite, painted layer, vector and cutout, 2.5D, low- or high-detail stylized and 3D approaches within rights and actual production capacity. Surface meaningful constraints before choosing a style. Describe references through design principles and original choices, and respect third-party IP and assets.

## Elements and states

Derive the inventory from actual scope. For each significant element or family specify ID, mechanical or communication role, view and scale, dimensions, proportions and pivot, shape, material, palette and light, visible states, motion and contact, cues, UI, audio and haptic events, variants, consumers and acceptance. Share tokens and recipes across repeated elements and record exceptions. Keep each rule authoritative in one place.

A character or agent needs applicable views, poses, silhouettes, movement, action, hurt, recovery, death or other states, gear attachments, and readable anticipatory cues. Items and vehicles need functional state, equip, use, cooldown, damage, recovery and changes from progression. World elements need material and state transitions, affordances, routes and hazards, depth and occlusion. UI needs normal, selected, locked, disabled, empty, loading, error and pending states, long translations and font scaling, input and focus, and safe areas. Bind each state to an actual rule and build the needed states.

For motion specify poses and curves, anticipation, contact and recovery, root and pivot locks, and appropriate limb limits, rigging, weights and IK. Include blend and cancel windows and simulation authority. A single PNG supports only observed image evidence. Align hands, feet and tools with surfaces and prove actual body movement. Test target and cue visibility during peak VFX overlap.

For audio specify motifs, timbres, tempo, texture, event mapping, SFX, music, ambience and UI needs, stems, loops, transitions, mix, ducking, voice priorities, interruptions and runtime routing. Verify the actual music by listening. For haptics define events, pattern, intensity, duration, cooldown, supported native playback and fallback. Evaluate feel on the actual device.

## Feasible references before presentation

A production profile records actual tools and versions and their installation, executable, authentication, permission, license and cost status. Include editable sources, sprite, model, rig and animation routes, export and import settings, materials, light, VFX, UI and audio capabilities, representative scene budget, target devices and open risks. Label verified routes, planned setup and unavailable capability separately. Verify API or external-service access separately from any subscription.

Generate a target the available route can plausibly reproduce. Bind prompts to gameplay camera, hero scale, visual density, animation representation, HUD and input, and constraints. If the promise depends on expensive cloth, fluid, geometry or animation, verify that route or adjust the proposal before presenting it. Surface a material fidelity tradeoff before the user chooses.

Inspect each generated frame against the approved description and production profile. Check framing, mechanic states, art language, body and contact, density, controls and HUD, and production plausibility. Record observer, hash and deviations. Give a sample-based independent review its actual scope. A preview records a visual proposal. Runtime and device observations require corresponding execution.

## Lock, lineage and parity

After owner acceptance preserve exact originals, hash, provenance and exact scope, including approved traits, allowed variation and known unknowns. Preserve bytes for an unchanged canonical asset. Give derived work its own recipe, source and import lineage. Link each element and state to its rule, accepted reference, authoring object, export, runtime consumer and evidence.

Before batch production reproduce a representative normal and peak scene in the actual native runtime with production sources and appropriate camera, aspect, state, seed, time, input, physics, HUD, animation, audio, haptics and applicable menu or commerce cues. Compare side by side, crop or overlay. Use documented pixel checks for static UI where useful and time-based observation for motion, contact and music. Keep fidelity claims scoped to the evidence. Keep quality-tier, LOD, compression and safe-area derivatives within accepted bounds. Reopen the owner decision for a material drop in fidelity.

## Dependencies, required evidence and roles

The art or creative lead owns direction. The technical artist verifies sources, import and performance. Animation, audio and UX specialists create actual materials. Runtime engineering integrates and an independent reviewer evaluates parity. Verify rights and licenses independently of creative ownership. Changes to camera, shader, rig, font, audio palette or interaction timing reopen affected source, runtime and UX checks.

Concepts need distinct evidence-based art direction, plausible production profiles and actual image inspection. Preproduction needs element and state specifications, quantities, budgets and the slice contract. The slice needs observed runtime, native and device evidence for each applicable modality before scaling. Beta includes human readability, feel and distinctiveness. Release needs assets, licenses and actual build and store parity. Live operations check identity continuity and new states. Counterexamples include color-only style variants, unknown source, tiny hero scale chosen only for poster composition, claiming a PNG as a rig, music that was only described, and claiming device fidelity from an editor frame.
