# Proportionate use of models, agents and context

> Apply the 4.0 contract in [maturity, competence and authority](v4/index.md) first, then the relevant domain sections. GA4-P1/D1/D2 extend GA3/UA26 and earlier IDs. Every complete concept needs C1 and production handoff needs T. Gather the evidence each gate requires and preserve historical sources and approvals. Apply R6 profiles, scale, style, camera and one-time kit choices only to their approved scope.

<a id="бюджет-перед-роботою"></a>

## Before spending resources

Record the desired output, tools actually available, facts to refresh, permitted expensive generation calls, allowed spend, planned checkpoints, and stop condition. Default to no additional spend. Check subscription limits and any separate API, CI or media cost.

Choose the model from the real host catalog without hard-coding names or prices. Use a sufficient lower-cost mode for routine formatting, search or local refactor. Use stronger reasoning for cross-domain architecture or critical review when it is available and justified. Change a user's model only within explicit authority.

<a id="команда-за-артефактом"></a>

## Artifact-based staffing

Use one orchestrator, a domain integration owner, relevant competence and independent review. Use a subprocess or subagent where independent work saves time or improves the result. If the subagent API is unavailable, work through the disciplines sequentially and record the actual actor and evidence.

Give each worker task ID, input paths and hashes, requirement IDs, writable paths, outputs, acceptance method, resource cap, and return scope. Return a summary, paths and evidence to the main chat and keep noisy logs in scoped files. Give one integrator ownership of shared writes. Put parallel code in isolated paths or worktrees.

Review levels:

- Local: a reversible change with the same contracts needs a focused check.
- Feature: an independent reviewer checks risk in the affected subsystem.
- Critical: physics, economy, save, purchase, identity and contracts need domain-specific independent checks and impact analysis.
- Stage: consider the actual artifacts and unresolved risk at handoff. Carry forward unchanged evidence when valid.

<a id="контекст-і-retrieval"></a>

## Context and retrieval

Use project files as the authoritative sources. Use chat for steering. Keep compact checkpoints, decisions, manifests, requirements indices and source or evidence links. Read the relevant IDs using `rg` or the file index. Use SQLite FTS when a sufficiently large text index helps. Remote vector RAG requires a measured need and budget.

Keep the source path, version or hash, and fragment context for each retrieved result. Distinguish superseded and accepted specifications. Derived indices are regenerable and project decisions retain their primary source. Native orchestration, explicit state and typed handoffs are the baseline. Adopt LangChain, LangGraph or embeddings when a demonstrated external need calls for them.

<a id="перевірка-без-зайвих-повторів"></a>

## Verification by changed dependency

Run cheap schema, path, hash, provenance, config and test checks, then reserve expensive media, human and device review for the current risks. A checksum validates bytes. Select tests by changed dependencies. Use broader checks before release or when new unresolved risks require them.

Batch a coherent repair and repeat its affected check. After two identical unsuccessful attempts, change the diagnosis, tool or question. Stop spending when a required capability is unavailable, and give the specific available route, cost and quality consequences, and decision needed.

<a id="докази"></a>

## Evidence

Distinguish hypotheses, paper or design reviews, simulation, automated tests, actual builds, devices, players and service-confirmed release. Player retention D1 or D7, monetization, and enjoyment require their own evidence. AI reviewers and simulations observe only their applicable scopes. Real players and hardware supply human and device evidence.

Close with the accepted artifact, observed evidence, persisted checkpoint, and exact next action when one remains.
