# Continuing a companion bot in ChatBot Atelier

One family serves new and existing bots. `chatbot-atelier-director` owns continuation. Research and specification handle initial analysis and domain model, conversation handles interaction, knowledge handles memory, integrations handle effects, jobs and groups, media handles assets, build implements, QA checks independently, release rolls out and operations maintains. Existing source and scope can be resumed without a prior agent package or previous integrator.

`assets/requirements.json` retains all 24 stable companion IDs. Keep the five domain teams and round/team tooling. Each stage includes the relevant contracts and can operate on its own. Required missing inputs or capabilities stay visible as gaps. Preserve capabilities and applicable project requirements through any change in how the workflow is triggered.

For an existing bot use the [current project guide](resume-current-project.md): **RESUME (ВІДНОВИ) → reconstruct actual repository, source and runtime → ask only material questions → draft a versioned plan → verify existing approval → execute the authorized scope and record evidence**. Reuse known facts and exact permissions. Scope reconstruction and planning separately from product mutations, deployment and external effects.

Project authority comes from the current user request, `AGENTS.md`, approved decisions and product contracts. Preserve domain rules and criterion IDs, persona, capabilities, privacy and consent, data and jobs, originals and approved assets, rights and budgets, source and runtime, and checkpoint. Family defaults leave project-owned policies in the project context. Track each affected requirement through source, owner, contract, evidence and receiving acceptance. Keep unknown impact visible.

The current handoff package carries real requirement IDs, exact inputs and outputs with hashes, scenario and approval scope, actual attempts and jobs, evidence limits, receiving owner and next action. Recover required facts from current authoritative sources when an older record format is unsupported. A cold receiver must be able to continue from the package and project context.
