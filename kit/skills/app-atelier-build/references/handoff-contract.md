# Environments, handoffs, pauses and delivery

Before switching environments, verify actual Work, Codex, local or cloud capabilities for files, tools, SDK, browser, network, accounts, signing and devices. A plugin or host name does not prove an operation or permission. A subscription does not pay for a separate API.

Keep one canonical source, manifest and version. Do not promise the automatic transfer of chat history, skills, browser sessions or credentials. Verify installation, discovery of the correct version and safe invocation separately. Resolve duplicate active sources by choosing one supported installation route on that host.

The launch/return package contains the request and scope, exact inputs and hashes, current requirements, decisions, knowledge and stop, capability gap, host/tool/version, real absolute working directory, a ready natural-language request or verified argv/UI steps, expected outputs and receipts, return files and path, validation and next action. Do not invent a Mac path, command, menu or tool ID. Complete the operation directly when it is available and authorized here.

Respect a pause now or at the specified boundary. Safely record the receipt or state of work already active without beginning new jobs after that point. Record completed, active and pending work, job/request IDs, unknown effects, limits and exact continuation. A resume does not grant a new execution or effect or repeat completed work.

An external effect requires a prepared artifact, parameters and target, current capability and exact authorization. Record the pending/dispatch state, make one actual call, then record its receipt and read-back. A timeout or missing receipt means unknown. Reconcile read-only first. Use provider idempotency where supported. A local journal does not guarantee exactly once execution at the provider.

The package includes actual source, instructions, profile and contracts without secrets, checks, verdict and gaps, manifest and hashes, setup and a separate product runbook. Self-contained modules have local shared references and runtime and do not rely on undeclared sibling paths. A package alone does not register a plugin, install it or run a service.

Safe import rejects path traversal, symlinks, special files, case collisions and unbounded archives. Do not automatically execute imported scripts. Preserve unrelated files, AGENTS instructions, state and data when updating. Show a concrete diff and save a backup before making an approved replacement after a conflict.
