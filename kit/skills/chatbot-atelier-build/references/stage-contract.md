# Stage contract for chatbot-atelier-build

## Visible result and applicability

Determine the task scope and a sufficient method using [adaptive work](adaptive-work.md). Apply [focused research and synthesis](research-and-synthesis.md) at any stage when it is relevant. The agreed project profile defines active functions, platforms and persona. Preserve established IDs, permissions, accepted results and full intent. Bind reviews to the exact observed source and version. A local repair uses the affected route and its applicable acceptance requirements.

Show why the chosen language, framework, storage and component boundaries fit. Provide an actual diff and end-to-end execution, relevant tests, exact source and the limits of mocked, integrated and live proof. Keep approved design and language requirements for the due stages.

## Establish the exact starting point

Restore repo/branch/SHA/tree and diff, relevant AGENTS, toolchain, environments, schemas, tests, assets and accepted functions. Select the implementation boundary from the domain contract, native capabilities, and receiver acceptance. Preserve actions, media and privacy in real code. Treat pseudocode, mocks and flags as preparatory evidence.

Choose language/framework/storage/SDK for the domain, supported tools, primary sources and quality needs. Compare complexity, ownership, cost, portability and performance. Use relevant language, data, security and testing guidance where available. Add queues, Redis, workflow engines or vector services only when the current scope needs them.

## Run the complete path and preserve recovery

Implement platform event → normalized scope → authority → atomic state and deduplication → provider effect → verified outcome → scoped delivery → recoverable checkpoint. Derive UI, prompt and persona feedback from the actual logical result. Keep schemas, APIs, events, tests, documentation and rollout consistent. Prove the same state after restart by reading the authoritative store. Report a mock success with missing client confirmation as partial.

Implement wrong actor, expiry, cancel, retry and reconciliation, restart, deletion and fences before scaling. Bound long-running media and jobs so they do not block chat. Preserve asset meaning, units, timing, sound and audience through transform/export/import. A sample cannot establish an entire set.

Compare baseline and candidate at the relevant boundary. Run build/static/type checks, targeted behavior tests, integration and negative tests by risk, and broader regression for shared or critical changes. Published checks do not require repeating without new cause. The author hands exact diff, outputs, commands, receipts, limits and recovery to an independent reviewer. Deliver runnable code/config, sources/assets, migrations, fixtures, tests/CI and known gaps without secrets. Execute deployment only with exact authority.

## Handoff

Provide stage ID, requirement and source IDs, exact versions and hashes, applicability and reason, typed rules, states and cross-system dependencies, capabilities and authority, operation contracts, recipes and effective parameters, actual attempts and job IDs, outputs and consumers, evidence and limits, negative cases, unresolved items, receiving owner and next acceptance check. The receiver can verify the finding without chat history. Return incompatible input or an infeasible requirement to the appropriate upstream owner.

## Criteria and completion

Check applicability for these criterion IDs first: practical_completion, execution_truth, bounded_resources, lifecycle_reliability, provider_constraints, version_continuity. Use all 24 baseline IDs for the impact map. Record active, carried or out of scope with reasons based on the current profile and accepted scope. Retain all approved requirements. For each active requirement record an owner, artifact, positive and negative checks, evidence kind, verdict, strongest objection and limits. Unknown evidence for a critical claim blocks the affected readiness. The author and independent QA are distinct. Human or production verification requires the actual applicable observation.

Deliver the complete requested result. Track concept, specification, production handoff, integration, live observation and human evaluation independently. When two attempts yield no new evidence, change the diagnostic hypothesis. A depleted budget leaves unmet acceptance criteria visible.
