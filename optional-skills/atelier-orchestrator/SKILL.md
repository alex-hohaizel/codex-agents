# Atelier Orchestrator1.0.0

One public integrator owns the whole result; actual specialists own bounded artifacts. Select the team from required competence, interfaces and risk, not a fixed roster. This optional skill is separate from the33core. It does not grant access, cost, publication, installation or product-migration authority.

## Restore and prepare

Restore original sources, native project identity/revision, all must/deferred requirements, accepted decisions/identity, current permissions, pending effects and stop. Use the [adaptive method](references/adaptive-work.md) and [context contract](references/context-capsule.md). A small repair stays bounded; a full product retains the full accepted target.

Read [briefing](references/briefing-protocol.md) for a new material choice and [interaction](references/interaction-protocol.md) for review/continuation. Inherit actual unchanged approval; do not repeat an answered questionnaire. Explain recommendation, alternatives and consequences when they materially affect the owner. Use the task contract in `assets/task-contract.json` as a projection, never a new authority.

Discover sufficient actual skills/tools by [source-pinned reuse](references/specialist-discovery.md); apply [research/synthesis](references/research-and-synthesis.md) to unknowns. Core directors/constructors are supported dependencies only when actually discovered/read: app→`app-atelier-director`, bot→`chatbot-atelier-director`, game→`gamedev-director`, new reusable agent→`agent-foundry`. Missing operation/source is blocked with a precise bridge, not an invented invocation.

## Produce and integrate

Apply [production quality](references/production-quality.md), applicable `assets/production-profiles.json` and [visual identity](references/visual-identity.md). Pin defining reference mechanisms, functional depth and accepted masters. Prove a representative slice on the actual medium before batch production. Semantic reuse does not force every exploration into one presentation template.

Create a finite dependency graph with task/component IDs, owner/competence, exact inputs/hashes, allowed paths/resources/effects, outputs/consumer, budget/stop, acceptance and recovery. Parallelize independent artifacts inside actual slots; serialize shared native state/account/device mutations. The integrator reconciles interfaces and due must across the whole product. An author cannot supply the independent verdict for their own artifact.

## Use the local service when available

First read `scripts/atelier_client.py --help`, then `status`/`doctor`; verify supported API, actual instance/project and capability. The client uses loopback-only HTTP with a fresh instance session and correlated CSRF; it never scrapes credentials. `prepare` creates a service-owned task/capsule; `dispatch` starts an actual supported job only within current scope. `interrupt` requests cancellation; reconcile actual terminal state before reporting cancelled. Server receipts and native source revisions are authoritative for the respective claim.

Use explicit project preview/binding, not a Home scan. Native requirements/decisions/identity remain in the project; the service provides projections and its own job/command records. Never replace unsupported native product state with a parallel ledger. A service owner review is not independent QA. Work audit/control is a separate host task and currently deferred.

If the service is unavailable, perform the approved bounded work through actual installed skills/controllers and maintain the native checkpoint; do not call a dashboard screenshot a running job. Apply the [Work/Codex bridge](references/joint-work-codex.md) and [tool compatibility](references/tool-compatibility.md) to the actual route. Unknown effects require reconciliation before replay.

## Review and return

Inspect actual output and distinguish source, craft, code, integration, device, independent and owner verdicts. Exact old evidence cannot be rebound to changed inputs. Return outputs/hashes, actual jobs/receipts, scoped checks, unresolved/unknown effects, current authority/stop and next allowed action. Cold continuation must work without hidden chat history. Preferred task/project language is respected; Ukrainian is the fallback.
