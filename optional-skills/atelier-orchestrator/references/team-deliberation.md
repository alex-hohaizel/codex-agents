# Deliberate with a team

Use this route when a decision benefits from different domain judgments or
the user asks for a roundtable. Keep a narrow repair direct. Start with the
decision, its owner, source links, fixed requirements and the choices that
are still open. Use the actual installed roles and project specialists.

## Set up the round

- For a quick discussion, the coordinator can present a few lenses within
  one response. Identify this as one model's exploration.
- For independent positions, assign a small number of different roles to
  the same source snapshot. Ask for an initial position, its strongest
  evidence, one objection to the expected choice and one observable result
  that would change the position. Collect these before showing the other
  positions. Keep write access with the project owner or next implementation
  role. Verify read-only enforcement if access needs to be restricted.
- The user can invite a role, ask a specific role to revisit evidence or
  change the question. Reuse initial positions only while their source and
  question still fit. If the host cannot run an independent role, disclose
  the missing viewpoint before synthesizing. A single voice exploring many
  lenses supplies ideas without independent review.

## Challenge and resolve

Share the actual strongest disagreement and relevant proof across the roles.
Ask them to test one material claim or explain what changed their initial
position. Give the user the resulting options, consequences, evidence and
remaining disagreement with role attribution. Stop when there is a decision,
a concrete next experiment or a question only the owner can settle. Avoid
forcing unanimity. A proposed resolution does not authorize a provider
operation, a changed product decision or publication.

For repeated work, retain the project-approved panel roster, role scope,
decision, evidence pins and open questions in project-local records. Load
them in a fresh round before resuming. Keep private transcripts out of
shared templates. Use the project’s current decision record to approve
or revise work and pass only the applicable choice and requirements to
implementation.

For a workshop that will span sessions, keep the decision question and
append completed rounds to the exact project record. Use the distribution's
`docs/technical/WORKSHOP.md` for reviewed catalogs, recovery, and the
Markdown or HTML report.

For a brief, PRFAQ, or design and experience workshop based on notes, use
`docs/technical/PRODUCT_FACILITATION.md` from the distribution. Keep
disputed positions in the draft and use a fresh reviewer after the
decision changes.
