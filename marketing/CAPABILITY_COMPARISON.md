# What this collection adds

This is a comparison of layers and workflows, not a claim that competing tools lack these capabilities. The host provides the models, tools, execution, permissions and any actual subagent runtime. This collection supplies reusable instructions, role definitions and project contracts on top of a compatible host. Using it does not create access to unavailable tools.

| Need | A compatible host can provide | What this collection is designed to add | Evidence to show before marketing it as achieved |
| --- | --- | --- | --- |
| A bounded architecture or integration task | Read code, reason, edit and run checks when the environment permits | A scope-first brief, relevant specialist roles and acceptance criteria | A representative brief, decision record and check results from the same task |
| A full application, chatbot or game | Coding, file creation, external tools and integrations when connected | Domain-specific lifecycle guidance, appropriate team roles and stage deliverables | The actual project artifacts, unresolved issues and platform-specific validation |
| Work across WORK and CODEX | Separate working environments, each with its own capabilities | An explicit handoff packet, retained requirements and a checkpoint-based return path | Matching project identifiers, source revision, requirement coverage and an independent intake |
| Upgrade a system used by an existing project | Version control and file operations | A migration path, project-delta review, recorded knowledge transfer and rollback evidence | A completed migration report for the project's previous and new versions |
| Make quality review repeatable | Tests, static checks and human or model review | Traceability from requirements to implementation and independent review instructions | Actual review output and relevant test evidence, including failures and limits |
| Keep design consistent | Asset creation and editing tools | An approved direction, identity rules and comparison between concept and final output | Owner approval, an identity manifest and checked final assets |

These are intended benefits of explicit workflow structure. They are not measured claims of higher quality, faster delivery, lower cost or better results than another named product. A future comparison must name the tool and version, date, task, environment, evaluator and measurement method. Publish the limitations alongside the result.

For a simple task, using fewer roles may be appropriate. A visual team diagram describes responsibilities; it does not mean every role runs in parallel or that all roles are needed for every request. A release agent prepares or carries out a release only within the permissions and scope actually granted.
