# Repository 1.4.0-rc.3 / Agent Atelier 0.3.1 — real-task evidence and compatible service repairs

This compatible source candidate adds actual, reproducible data/model/media evaluation tools and compatible local-service focus/artifact-selection repairs. It retains core 6.1.0, Orchestrator 1.2.0, maintenance 1.1.0, all 33 stable core skills, two optional sources and 12 roles. It introduces no required framework, installed model, global registry, database/API migration, new skill name, identity change or paid provider.

The service patch keeps task-dialog focus inside the dialog and preserves restoration/keyboard behavior. Artifact selection is stable across refresh by project/path, uses the current artifact metadata and cannot leak the prior project’s selection. Background-refresh failure clears unavailable workspace/inspector data and shows recovery rather than retaining stale proof. Markdown artifacts use the existing readable report view, bounded authorized source reads and original-file hash/size/path checks. Declared pins must match; unbound files remain source-only observations. Display text may be redacted without changing the original-file SHA. Relative paths distinguish homonymous files. A different explicit selection reveals the preview heading without focus theft or smooth motion; polling does not scroll the page. Read failure retains retry/original download, and changed metadata or bound-source pins refresh the selected report. The accepted layout and permission boundaries remain. Source version 0.3.1 is separate from an already running build. An installation, restart, discovery and actual runtime check require their own receipts; the preceding rc.2 proofs do not certify the changed source.

An optional advanced task API field `memory_mode` defaults to `inherit`, preserving ordinary tasks and global preferences. Explicit `disabled` is limited to fresh service-owned task chats: false memory-use/generation config from first start, native setter acknowledgement before a turn and task-only memory-file denies. Adopted user native chats reject disabled so their persisted setting is not changed. The supported Thread schema provides no independent mode readback; an acknowledgement is not proof of absent injection. Initial/R2/R3 source-only context trials remain NOT_ADMITTED; three R4 cold retests are pending. This restriction does not turn all readable project files into approved task evidence. See the [advanced field contract](../docs/evolution/2026-11-10/REAL-WORLD.en.md).

Selected skill inputs now use a separate immutable execution namespace with exact task/manifest ownership; private control archives stay under the existing data directory. Only the selected subtree receives the existing narrow read grant. Canonical/archive/execution drift or a stripped/empty task-owned selection set blocks dispatch. Explicit retention cleans only the owned derived subtree. Legacy capsules are not silently rebound. The current service backup remains STORE JSON metadata, not archive-file backup; a full owned-data filesystem backup is separate before live replacement.

The new [real-task handbook](../docs/evolution/2026-11-10/REAL-WORLD.en.md) and its [Ukrainian edition](../docs/evolution/2026-11-10/REAL-WORLD.uk.md) explain the 34 reusable evaluation files, their triggers, inputs/outputs, consumers, access, tests and recovery. Raw issue/review data, authors, weights, private paths and detailed local receipts remain outside these sources.
