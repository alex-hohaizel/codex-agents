# Repository 1.3.0 / Orchestrator 1.1.0 / Agent Atelier 0.2.0

This release turns the existing optional orchestrator into a universal entry for an outcome, a project or maintenance of the agent system. It also extends the local workbench from explicitly connected projects to a source-backed portfolio of available Codex work, including native history started outside the service. The owner approved the universal-entry passport and clarified project-agent continuity, a useful visual work map and maintenance of the system itself.

## Universal entry

Describe the needed result without selecting internal skill names. The orchestrator chooses an appropriate route: direct work, an existing specialist, an existing project agent, a domain director, component coordination, agent construction, system maintenance or an exact host bridge. A small request does not require a new agent or a full product process. Source-backed specialist selection remains an expert decision; a route proposal or structural checker is not a semantic-quality oracle.

There is one brief and one integration owner. Existing requirements, decisions, identity, permissions and native state follow delegated work. When a project agent is created, checked and actually discovered, the orchestrator recommends continuing through it and retains that binding if the owner later returns to the universal entry. Creating an agent and executing the owner's original task remain different scopes and acceptance conditions. A skill package cannot close a requested product.

The maintenance route covers the orchestrator itself, a skill, constructor, family or existing project agent. It reads actual target sources/settings, prepares an impact and diff, preserves local work and identity, retains before copies and verifies the actual saved source. Self-maintenance cannot authorize itself, rewrite the authority of a running task or retroactively attach old evidence to new bytes.

The optional source now includes the previously missing local specialist-discovery helper, typed component-handoff checker and template, with exact source pins. The additive task projection and `check_routing.py` separate delivery, execution and acceptance declarations. These checks perform no installation, network operation, model call or consent authentication.

## A portfolio of actual work

The service reads supported Codex history with explicit pagination/coverage and groups available work by project and task. It retains source provenance, inaccessible or incomplete coverage and the distinction between a discovered folder and an explicitly connected project. It does not scan the owner's Home directory, read a private host database or turn discovery into product-write authority.

The workbench presents project goals, documented work, source relationships, project-agent status and next useful actions. Accepted goals require a source of recorded acceptance; inferred or source-declared text is labeled separately. An assistant answer is not product acceptance; a skill mention is not execution; a planned agent is not installed. Work started directly in Codex is inspected through supported native history, not recreated as a fabricated service job.

Native paginated history is read through a dedicated read-only public-API transport using the native index. The isolated model executor keeps its own index and permissions. Missing or empty history stays partial; metadata is not execution context. Native chat continuation is blocked if that executor cannot restore its persisted history; a fresh bounded project task and continuation in the capable native host remain distinct options.

Typed native system permission checks remain separately inspectable instead of inflating user-result lanes. Cross-page native/service observations correlate by actual thread/turn identity while retaining service linkage, recorded owner review and evidence.

The universal-entry view lets the owner state an outcome, review a proposed route and prepare the next bounded task. Actual launch still uses supported capabilities and current authority. Existing active or unknown native writers cannot be taken over by a service lease. Protected native-state mutations use an owner-reviewed controller preview/apply route with exact source/state pins and fixed supported operations; a model job cannot simply write protected state files.

The panel also exposes reviewed updates for the two known optional orchestration/maintenance sources: exact preview, apply with a private before-copy, full-tree verification and a guarded rollback that refuses later unknown edits. Installed source bytes, refreshed host discovery and actual execution retain separate statuses. This bounded updater does not replace the existing33-core updater or modify arbitrary vendor/plugin caches.

## Compatibility and limits

- Repository edition: 1.2.2 → 1.3.0.
- Optional `atelier-orchestrator`: 1.0.1 → 1.1.0. Stable selector, invocation policy, original icon assets/bindings, system class and brand color remain preserved.
- Agent Atelier: 0.1.1 → 0.2.0. Preserve the existing service data directory, project bindings and histories; reconcile jobs and prepare fresh dependent context when its pinned inputs change.
- Core suite: 6.0.0, unchanged. The33stable names and existing core icon/source preservation remain in force. No core reinstall or unrelated product migration is implied.
- Native product formats and ownership remain authoritative. New service-owned projections do not become a second product requirement registry or an approval store.
- All seven complete guides and service locales cover the affected flow. The accepted operational visual identity is retained.
- WORK live audit/update/control is explicitly deferred until access is restored. A Codex source update, archive, delivered message or beautiful panel is not a WORK installation or execution receipt.

See [the exact update and rollback procedure](migrations/repository-1.3.0.md). Actual installation, native discovery, representative execution, independent review, package hashes, publication and exact-ref CI are recorded after those operations occur. Historical model and release evidence retain their original source scope; this release makes no universal quality or future model-behavior certification.
