## Steps

From a separately trusted checkout, bind the verified stable release to the updater. Set the shell variables below to the approved record and fresh private paths. Obtain release pins independently of the downloaded archive. Use `refs/heads/main` for the canonical Actions run and `.github/workflows/validate.yml` for its signer. Rehearse on a clean fixture first.

```sh
set -e
python3 -B scripts/admit_codex_bundle.py \
  --archive "$downloaded_codex_zip" --stage "$new_stage" \
  --source-sha "$approved_commit" --source-ref refs/heads/main \
  --signer-workflow .github/workflows/validate.yml \
  --archive-sha256 "$approved_archive_sha256" --manifest-sha256 "$approved_manifest_sha256" \
  --repository-version "$approved_repository_version" --suite-version "$approved_core_version" \
  --installed-suite-version "$verified_installed_core" > "$admission_receipt"
admitted_kit="$(python3 -c 'import json,sys; print(json.load(open(sys.argv[1]))["kit"])' "$admission_receipt")"
python3 -B kit/portable/update_skill_suite.py audit --kit "$admitted_kit" --plan "$new_core_plan"
python3 - "$admission_receipt" "$new_core_plan" "$approved_manifest_sha256" <<'PYTHON'
import json, sys
with open(sys.argv[1], encoding="utf-8") as file:
    admitted = json.load(file)
with open(sys.argv[2], encoding="utf-8") as file:
    plan = json.load(file)
if (admitted["status"] != "admitted-for-updater-audit" or not plan["ready"]
        or admitted["kit"] != plan["kit"]
        or admitted["manifest_sha256"] != sys.argv[3] or plan["manifest_sha256"] != sys.argv[3]):
    raise SystemExit("The updater plan differs from the admitted kit")
PYTHON
```
