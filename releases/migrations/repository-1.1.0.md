# Repository edition 1.0.0 → 1.1.0

This migration updates documentation, the selected bilingual campaign and compatible repository tooling. The reusable suite remains **5.0.0**. It is separate from installing or adopting a different skill-suite release.

## Before

1. Confirm the repository revision and inspect local changes. Retain uncommitted work and local customizations before updating the checkout.
2. Read the 1.1.0 release record and the exact commit supplied with the completion report. Repository visibility and access permissions remain unchanged.
3. For an existing product, retain its accepted requirements, design identity, decisions, native schema/state, toolkit lock, deployment revision and current checkpoint.

## Steps

1. Update the documentation/source checkout to the reviewed 1.1.0 revision using the host's supported repository workflow. Reconcile local changes; do not overwrite unknown edits or force a reset.
2. Replace saved advertising links with `marketing/campaign/README.md` for English or `marketing/campaign/README.uk.md` for Ukrainian. Repository galleries start at `marketing/campaign/index.html`; localized pages are `en.html` and `uk.html`.
3. Use `marketing/campaign/pdf/Campaign.en.pdf` or `Campaign.uk.pdf` for compact downloads. Download the repository/package when using the portable gallery, so its local image paths remain available. Standalone full-quality exports are delivered separately.
4. For future advertising, read `marketing/CURRENT_CAMPAIGN.json`, keep the exact Ukrainian source-cover hash and continue the selected product identities. Retired concept galleries are no longer current references.
5. In Work or Codex, continue the **same existing product** from its checkpoint. Read the updated repository instructions before the next dependent task. A documentation/campaign update does not install a skill or create cross-session memory.
6. Keep the currently verified 5.0.0 skills and their icons. No reinstall, duplicate global installation, product reset, generated-agent version bump or native-state migration is required by this edition.

## Verify

Confirm the selected language entry, current campaign files, source manifest and release metadata. Run source/repository/campaign checks and inspect the actual remote revision. Source integrity, archive integrity, visual localization, runtime discovery and product acceptance remain distinct results.

## Rollback

Restore the previous documentation revision or old saved links if needed, retaining current local work first. Old advertising remains accessible through Git history. This edition changes no product state to reverse. Do not roll back an independently updated product or skill installation merely to change the marketing edition.

## Existing projects

Keep all accepted product requirements, permission boundaries, design identity and unfinished tasks. If a project separately adopts a new toolkit behavior or source release later, use its own source-to-target mapping and the suite migration. Edition 1.1.0 alone does not perform that adoption or replace native schemas.
