## What changed in v1.8.0

- One local browser wizard wraps the existing plan, install, verify, discovery,
  recovery and uninstall engines. It requires approval of the exact saved plan.
- Ready Universal and six smaller platform packages include pinned Python3.13,
  Node24, PyYAML, complete source resources and the compiled workbench client.
- Windows has actual byte locking, private ACLs, process queries and path guards;
  existing POSIX protections and project environments are preserved.
- Windows personal skills use the supported `CODEX_HOME/skills` root. Reviewed
  migration preserves known previous core/Orchestrator sources, supported core
  icon tuning, acquired rights and recovery at each journal's original paths.
- Native package acceptance covers actual interruption, writer exclusion, existing
  work, discovery, real browser controls and workbench backup/schema recovery.
- A completed rollback retains the checked identity of the preceding launcher,
  allowing a new reviewed update while continuing to block unknown local edits.
- `START_HERE.html` and its Ukrainian entry are visible in source downloads too.
- Private installer/workbench reads use origin-scoped authorization; refresh,
  live events and artifact previews retain the protected buyer workflow.

See [the platform/evidence contract](../governance/UNIVERSAL_INSTALLATION.md),
[installation](../docs/INSTALL.md) and the exact release workflow receipts.
A native runner proves its declared OS/CPU case, not every OS version or device.
Unsigned product launchers and platform warning handling are documented.
