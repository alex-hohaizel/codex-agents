# Interaction and fidelity criteria

- Riverdesk starts on the three-item queue. The operations board shows a separate source pane at desktop width and stacks it below the queue at phone width. Selecting a queue item updates the title, provenance, and action target. The operator may transmit only a reviewed report. A viewer may read the same evidence and lacks the transfer action. An optimistic conflict preserves the item, offers a refresh action, and supports a fresh transfer with an exact-ID receipt. The local harness injects the conflict and uses a browser emulation for a phone viewport. The role switch is an evaluation control for demonstrated UI behavior. Server-side authorization is outside this fixture's scope.
- Riverlines starts as a public reading page with a main editorial lead, a chronology following the river from upper to lower reach, and article-specific provenance. Choosing a reach changes the article; opening field notes reveals the cited source without replacing the article. The public page has no queue, approval control, or handoff route.
- Keep the exact master files, shared report data, styles, controls and outcomes together. Riverdesk uses a navy operational surface with a gold selected row and separate source pane. Riverlines uses ink on cream, a bright orange editorial signal and an enlarged serif headline. The actual actions and information hierarchies determine product identity. At narrow width reading order takes precedence over matching desktop positions.
